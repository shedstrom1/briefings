## Models and local inference

**GLM-5.4 — z.ai ships its first Loop Transformer flagship on the Coding Plan**
Released 2026-11-23 (announcement ~04:18 UTC). Z.ai's lead Zixuan Li posted that all GLM Coding Plan subscribers can now use GLM-5.4; it adds vision and "stronger all-round coding performance" and — for users on weekly quotas — 50% more quota than GLM-5.3 on the same plan tier. In Claude Code the model id is `glm-5.4[1m]` (1M-context suffix); other tools use `glm-5.4`. The technical blog (z.ai/blog/glm-5.4) describes the first model built on the Loop Transformer architecture: 28 shared layers run twice on a roughly 750B-parameter GLM-5 base, with per-token gates controlling how each pass updates the hidden state, hybrid KV-cache (the second pass reuses sparse attention indices and part of the first pass's KV cache), text+image input, 1M context, and demos for code across video effects, games, interactive 3D and FreeCAD mechanical design. Z.ai reports serving throughput of 70–80 tok/s at peak and up to 200 tok/s off-peak. Benchmarks come only from a 30B ablation (AIME25 19.17→30.42, GPQA-Diamond 47.58→56.26, AA-LCR 40.33→47.67, MMLU-Pro 71.65→75.05, IFBench 50.20→53.47; ~2–15% shorter outputs) — the flagship's "2T–3T model-class intelligence" claim has no public per-benchmark comparison. No weights yet ("released responsibly", after safety hardening) and no standard API access (after safety evaluation); no parameters, cutoff or output-length specs published. No open-weight release this window.
Why it matters: the first Loop Transformer flagship aimed at practical coding agents rather than benchmark froth — the commercial surface (Coding Plan + Chat) comes first, the weights later, which changes the local-inference framing.
Local inference note: no local variant yet. Watch the "release responsibly" weight promise and the API/pricing drop; the credit multipliers (input 4.6, cached input 1.1, output 16) are cheaper than GLM-5.3's (6.9/1.7/24).

## AI security and governance

**OpenAI chief scientist Pachocki: perplexity as the shared safety metric — and proposed limits**
Published Nov 22, 2026 (Reuters datelined Nov 22): OpenAI Chief Scientist Jakub Pachocki argues that pretraining progress — measured as log-perplexity / cross-entropy loss — is the best single proxy for general capability and proposes establishing it as an industry metric, with shared norms for evaluating and red-teaming models before first use and a first limit, before any lab crosses the estimated ~0.68–0.70 log-perplexity window (OpenAI now sits below 0.8, with transformative cybersecurity and mathematics capabilities emerging there). He published OpenAI's internal perplexity measurements on a held-out codebase dataset (GPT-3.5 at ~0.99, GPT-4 at ~0.91, GPT-5.x below 0.8) as a first step. "The sharper the compression, the bigger the leap" — AI-assisted research has sped up the pace of progress; ~0.76 unlocked groundbreaking mathematics results, and the 0.68–0.7 window may unlock more, possibly reaching ~1 trillion-scale pretraining design improvements by 2027. He acknowledges limits: cross-lab comparability (different training mixtures), detachment from actionable evaluations, and that chain-of-thought reasoning doesn't reduce perplexity.
Why it matters: the industry is proposing a norm — common metric, common transparency, common development limits — that would constrain how fast frontier models are trained rather than only how their surface behavior is governed. The catch: perplexity is a pretraining-only metric and doesn't capture the post-training gains that actually produce agentic capability, so the metric is a floor, not a ceiling, for risk.
Source: OpenAI blog — https://openai.com/index/perplexity-and-intelligence/ (Nov 22, 2026) · Silicon Report summary — https://www.siliconreport.com/openai-chief-scientist-proposes-perplexity-as-shared-safety-metric
