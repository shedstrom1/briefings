## Vulnerabilities and patches

**N-able mail-assure SSRF (CVE-2026-134624)** — November 22, 2026. The Hacker News / N-able advisory.
N-able disclosed — in the wake of the Nov 16 Mail Assure / SpamExperts Hosted Cloud outage — a critical server-side request forgery flaw it found while investigating the breach. CVE-2026-134624, CVSS 4.0 9.3, lets an authenticated API user with high-level access point Mail Assure's LDAP-sync connection check at arbitrary internal hosts and ports, probe which answer, and send crafted data to them. The bug lives in the relay-connection check; builds before 20261121.1943 are affected, and the fixed build carries the same stamp. Dashboard and APIs were restored late Saturday, closing the outage that began last Monday; email delivery and spam filtering never failed. Whether the flaw was the attacker's way in is not established — N-able has not said — and no evidence of other exploitation has surfaced.
Why it matters: this is the second critical remote-code-style foothold N-able has had to ship in two weeks, and the company is still rebuilding hosted customers' trust — revoked tokens, an unconfirmed attacker-path, and a 2-week forensic RCA.
Action: hosted customers reconnect with new API tokens and OAuth credentials; Local Cloud operators (self-managed SpamExperts) should confirm their servers run build 20261121.1943 or later.
Source: The Hacker News, "N-able Discloses Critical Mail Assure Vulnerability Found During Breach Investigation", Nov 23, 2026 — thehackernews.com/2026/11/n-able-discloses-critical-mail-assure.html ; N-able security advisory (me.n-able.com) for CVE-2026-134624.

**binary-parser code injection (CVE-2026-134814)** — November 22, 2026 (maintainer advisory Nov 11). The Hacker News / vulncheck.com.
The popular Node.js parser `binary-parser` before 2.3.1 fails to validate string-typed options (length, lengthInBytes, key, tag, offset, namely() alias) passed through Context.generateOption(), letting an attacker who controls the parser definition inject and execute arbitrary JavaScript in the host Node.js process at compile time. CVE-2026-134814 is rated CVSS 4.0 9.2 Critical (8.1 v3); CWE-94. This is also an incomplete-fix recurrence of CVE-2026-1245 (6.5), fixed back in January 2026. It is not in CISA KEV and carries EPSS < 1%. The maintainer (keichi) is explicit that parsing untrusted binary data with a trusted definition is not affected — the risk is parser *definitions* coming from untrusted input.
Why it matters: this is a critical, narrowly-scoped library bug that is cheap to enumerate (npm lockfiles) and trivial to kill with a one-line bump — the same pattern as prior library-class flaws this quarter.
Action: upgrade to binary-parser 2.3.1 or later; do not let users supply parser definitions directly.
Source: The Hacker News, "Critical binary-parser Flaw Enables JavaScript Injection", Nov 23, 2026 — thehackernews.com/2026/11/critical-binary-parser-flaw-enables.html ; OpenCVE/NVD advisory, Nov 22, 2026.

**Idunno.AntiCsrf — exploited in the wild, no patch (CVE-2026-131914)** — November 23, 2026. Daily Security Review / The Hacker News / Google Cloud & Mandiant credited.
A critical insecure-deserialization flaw in `Idunno.AntiCsrf.AntiCsrfModule` (Idunno.AntiCsrf), an abandoned ASP.NET WebForms CSRF-protection module unmaintained since December 2008, is being exploited in the wild and has no fix. CVE-2026-131914, CVSS 9.3. The 0.9.1.0 and 0.9.1 Beta releases deserialize untrusted CSRF-token data with an unkeyed System.Web.UI.ObjectStateFormatter — no MAC or signature check — so one unauthenticated HTTP POST carrying a Base64 .NET gadget chain in the CSRF form field plus any non-empty cookie executes code as w3wp.exe, the IIS worker process. Mandiant (with Google Cloud researchers) rate exploitability "High" and gave the alert week of November 16; research coverage and the weekly-recap re-cover are dated today. No patch will arrive; the project is defunct.
Why it matters: it is a clean reminder that "abandoned" is not "safe" — one request, no auth, no credentials, full server compromise for any WebForms app that still loads the module. No CVE-to-KEV mapping and no indicator is published beyond the request pattern.
Action: inventory ASP.NET WebForms applications for Idunno.AntiCsrf and remove or replace the CSRF protection it provides; check IIS worker-process activity before/after.
Source: Daily Security Review, "Idunno.AntiCsrf Flaw CVE-2026-131914 Exploited With No Patch Available", Nov 23, 2026 — dailysecurityreview.com/resources/idunno-anticsrf-flaw-cve-2026-131914-exploited-with-no-patch-available/ ; The Hacker News, Nov 23, 2026 — thehackernews.com (binary-parser twin article; the homepage thread).

## Attacks and campaigns

**GlobeTopper/iQSTEL breach and SEC filing** — November 23, 2026. BleepingComputer / iQSTEL SEC filing.
B2B digital gift-card distributor GlobeTopper (parent iQSTEL) reported — in an SEC filing — that an intrusion detected on October 22 exposed "certain client API credentials and integration keys of certain GlobeTopper business customers." The company took the platform and all affected servers offline in the early hours of October 23, rebuilt on AWS October 31, and restored commercial operations in stages starting November 1. The platform — used by 4,000+ brands across 65 countries — lost an estimated ~$2.5M in fourth-quarter revenue, and the attacker redeemed digital gift cards worth $70,000 that the company cannot recover. All revoked credentials and integration keys have been rotated; affected business customers have been issued new credentials with additional access restrictions. No ransomware group has listed iQSTEL or GlobeTopper on extortion portals. The disclosure was made today via SEC filing and BleepingComputer.
Why it matters: this is a live supply-chain-style incident — a B2B platform with 4,000+ customer integrations — and the disclosure came a month after the attack, ahead of the holiday season. Customer-facing revenue impact is real but the group is unconfirmed and data beyond the api keys remains undetermined.
Action: affected GlobeTopper business customers should confirm with their integration partners that new credentials are in place; no further vendor action is specified.
Source: BleepingComputer, "GlobeTopper loses $2.5 million after hackers steal $70k in gift cards", Nov 23, 2026 — bleepingcomputer.com/news/security/globetopper-loses-25-million-after-hackers-steal-70k-in-gift-cards/.

**AIR WebSec benchmark — AI coding agents get malicious search results** — November 23, 2026. The Hacker News / air.security.
AIR Research Lab released the WebSec Benchmark, the first benchmark of how secure web search is for AI coding agents. It sent 4,719 real coding-agent search queries across eight widely-used search APIs — Firecrawl, Tavily, Perplexity, Parallel, Exa, Nimble, Brave, and You.com — and checked all 282,000+ results returned. All eight engines handed at least one known-malicious result. Across ~37,700 searches, 534 surfaced known-malicious content, and agents were handed malicious or risky results 1,026 times. Per-API hit rate ran 0.8%–2.2% (one bad search in every 45–125); rates were highest on install and package searches, where an agent is about to run code. Firecrawl (21.59) and Tavily (18.59) scored best on the WebSec Index; You.com (5.02) scored lowest. AIR has also documented that ~1 in 55 everyday developer queries returns results on unregistered, re-sale-eligible domains — and a Solana-Kit-style starter-kit shock.
Why it matters: the install/package query path is where AI coding agents go wrong, and the threat is invisible to human review — no click, no approval prompt. This is not hype; it's a measurable, benchmarked rate.
Action: turn off auto-approval for installs from unchecked sources, verify packages before running, and log what agents read — not just what they run.
Source: The Hacker News, "AI Coding Agents Are Getting Malicious Results From Web Search Indexes, WebSec Benchmark Finds", Nov 23, 2026 — thehackernews.com/expert-insights/2026/11/ai-coding-agents-are-getting-malicious.html ; AIR WebSec blog — air.security/blog-posts/websec.

**Australia's Commonwealth Bank (CBA) open-sources CodeCheck** — November 23, 2026. The Register (Simon Sharwood) / CBA GitHub.
Commonwealth Bank of Australia released CodeCheck, a free AI-powered tool that scans its bespoke code for bugs — an analysis of the output of OpenAI's Codex and Anthropic's Claude Code, using a consistent process for analyzing the code, investigating potential vulnerabilities, and providing information to help engineers. CBA posted the tool to GitHub and warns it is a one-time open-source release for businesses to evaluate — the bank will not actively maintain, update, or support it. The tool is not identical to CBA's internal systems.
Why it matters: the first major Australian bank to publish an AI-powered code review tool, in direct response to a 2026 toolchain trend where AI agents are themselves the code-writing surface. Free, not maintained — useful as a baseline benchmark.
Action: evaluate CodeCheck as an internal-dev-side tool; do not ship unvalidated AI code without human review.
