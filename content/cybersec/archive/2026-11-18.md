## Vulnerabilities and patches

**CISA orders immediate Java4Shell patching; alert goes federal-grade (Nov 17 evening)** — *Update on previously reported (ledger: CVE-2026-114938 / Java4Shell + Oracle CSPU, Nov 17 12:20 & 17:20 fires).* The alert was posted Nov 17 at 5:30 p.m. ET and distributed via GovDelivery at 5:46 p.m. ET — after the previous fire's cutoff, so it was not covered then. CISA "strongly urges" patching CVE-2026-114938, calling it a critical memory-corruption bug in the Base64 decoder of the x86-64 HotSpot JVM where crafted Base64 input can crash the JVM and allow unauthenticated remote code execution. It explicitly warns that vulnerable JDKs/runners may not appear as separate inventory entries because they are **bundled inside third-party applications, container images and appliances**, and lists compensating controls if patching can't happen today (restrict/validate Base64 at the app boundary, input-size limits, limiting unauthenticated access) plus hunt signals (rogue runtimes, unexpected JVM crashes). The Canadian Centre for Cyber Security co-authored. Severity remains disputed as previously reported: Oracle CVSS 3.1 8.1 (High) vs the researchers' CVSS 4.0 9.2 (Critical).
Why it matters: a CISA "Alert" (not a routine advisory) days after disclosure is an escalation that federal BOD timelines and enterprise patch queues will follow — and it validates the field's concern that the biggest exposure is unmanaged Java embedded in appliances, not OpenJDK on servers.
Action: inventory JVMs including bundled ones; prioritize internet-facing Java services; apply Oracle/OS-vendor builds now; if blocked, deploy the Base64 input controls and monitor for JVM crashes.

## Attacks and campaigns

**Microsoft's official `agent-framework` PyPI package shipped a credential stealer in two versions (published Nov 17, disclosed overnight Nov 17–18)**. Attackers published versions **1.26.1 and 1.26.2 of `agent-framework`** — the meta-package for Microsoft's AI-agent framework — 33 minutes apart on Nov 17 (1.26.1 uploaded 20:35:20 UTC per a public GitHub issue), quarantined by PyPI roughly 45 minutes later. Each wheel drops a `.pth` file in site-packages (`agent_framework_meta.pth`, `af_runtime_diag.pth`), so the payload executes on **every Python start** — including pip itself — whether or not anything imports Agent Framework. It harvests substring-matched environment variables, Azure CLI and npm/pip/netrc/git-credentials/Docker/HuggingFace credential files, **Azure DevOps OIDC tokens, Azure managed-identity tokens via IDENTITY_ENDPOINT/MSI_ENDPOINT/IMDS (169.254.169.254)** and instance metadata (up to 8,000 chars), asks the platform to *issue fresh* credentials (so rotating stored secrets isn't enough), and 1.26.2 additionally grabs **GitHub Actions OIDC tokens** and widens the env-var net. Exfil is a zlib+Base64 HTTPS POST to a hard-coded webhook.site URL. The package draws ~190,000 downloads/month; the exposure window the researchers publish is 20:35–~21:20 UTC Nov 17. How publishing access was obtained is unknown; OX Security's read is that the wheel-creation flow was hijacked. Severity: Not specified by source (no CVSS published). This is the second Microsoft-named PyPI package compromised in 2026 after durabletask (TeamPCP, May).
Why it matters: this is exactly the AI-development supply chain that 2026's breach wave (LiteLLM, Trezor/Skladdon, Cursor marketplace) keeps hitting — the .pth startup hook means one `pip install` silently persists a stealer across every future Python run in the environment, and the tokens it targets federate straight into cloud and CI privileges.
Action: pin `agent-framework==1.26.0`, isolate suspects, sweep for `agent_framework_meta.pth`/`af_runtime_diag.pth` in site-packages, hunt proxy/DNS logs for `webhook[.]site/d381fd80-ec62-42ad-8f5c-d1b15103c9bb`, rotate all Azure/GitHub credentials from clean systems, and audit Azure DevOps and GitHub Actions workflows that deploy to Azure.

**Google: FSB-linked COLD RELIC chained one stolen Google Workspace tenant into a second U.S. breach (report published Nov 17, covered overnight)**. Google's Threat Intelligence Group and Mandiant published an end-to-end case study on COLD RELIC (formerly COLDRIVER/UNC4057, aka Star Blizzard, Callisto, Gossamer Bear) — a group DOJ assesses operates inside the FSB. In late 2025 the group entered a U.S. organization using **stolen Super Admin credentials from a residential proxy near the victim plus an MFA-push fatigue attack**, registered an unseen device model, then **bulk-shared and downloaded the entire tenant's cloud drive**, exported the full employee list, kicked off a tenant-wide **Google Workspace Customer Takeout**, and deleted its own Alert Center notifications as anti-forensics. Attacker-enrolled **passkeys survived password and session resets** — some were never revoked — and were reused for months. After being evicted, COLD RELIC pivoted: posing as an employee of victim one over an encrypted messaging app, it phished a second U.S. organization whose Entra ID federated into Google Workspace, registered a rogue MFA device there, and bulk-downloaded files; a June 2026 VirusTotal-submitted redirector URL contained a parameter naming the first victim. GTIG says new COLD RELIC phishing operations continue as of November 2026, and Google issues Government-backed attack alerts on this activity; SecOps detection rules are named (MFA-fatigue success, Customer Takeout initiated, Alert Center deletion, user-list download, passkey enrollment after fatigue, etc.).
Why it matters: the report is a clean public dissection of *credential + trust* compromise in cloud suites — no malware, no zero-days — and the Customer Takeout/impersonated-colleague techniques give defenders concrete log events (`CUSTOMER_TAKEOUT_CREATED`, external-share spikes) to alert on rather than vague TTP talk.
Action: disable Takeout org-wide if unused; alert on the named log events; after any suspected compromise, explicitly revoke passkeys, backup codes and enrolled devices — password resets alone leave COLD RELIC inside.
