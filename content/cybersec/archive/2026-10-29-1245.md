## Vulnerabilities and patches

**Telegram Android: answer a call, lose the phone — code execution via malformed MediaState messages (disclosed today, Oct 29)**
Security startup NebuSec disclosed today a flaw in Telegram for Android that let an attacker run code on a victim's phone over a voice call once the victim answered — only an ordinary Telegram account was required. The bug lived in the code parsing MediaState call-setup messages (mic/camera/rotation state), which read memory for fields the message didn't carry; every version from 8.6.2 (March 2022) through 12.10.3 is affected, and Telegram fixed it in 12.10.4 released in late September. The tgcalls library's "Fix camera rotation" patch landed on iOS in 12.7 (May) and desktop in 7.0.1 (July), with Android last; no CVE exists as of today, and there's no evidence of exploitation in the wild. Separately, ZDI's Oct 15 advisory covers an unpatched rlottie flaw, CVE-2026-111105 (CVSS 7.0), chainable to code execution when a user opens a malicious file or page.
Why it matters: call-triggered RCE in a messenger with hundreds of millions of users is an access vector that survives every attachment filter, and the AI-fuzzed discovery path (NebuSec's product runs on GPT-5.4) plus the still-open rlottie bug say the Telegram attack surface isn't mined out yet.
Action: update Telegram for Android to 12.10.4 or later now (Settings page shows the version).

**EMBRACE: embedded browsers in VS Code, Cursor, Copilot, Codex and Claude Desktop all broke a core browser-security rule (published today, Oct 29)**
Forever Security published "EMBRACE" (embedded browser trusted like a real one) research today showing that in all five major AI coding assistants, loosened embedded-browser rules let a web page or a local file reach the host: Cursor would run attacker code off a "Start setup" button (agent even disabled its own sandbox unprompted), Copilot let a page forge its own address bar (a fake github.com/login), and Codex, VS Code and Claude Desktop let one HTML file in a "trusted" project read the entire disk via a web worker outside the folder check — collecting SSH keys, .env files and npm tokens in their test. Cursor patched Oct 1 and GitHub fixed Copilot in 1.1.29 on Oct 13, but Codex and VS Code had no fix as of today; Anthropic and Microsoft declined the reports citing Workspace Trust, which researcher Gal Weizman says "provides zero protection" since everyone clicks Trust.
Why it matters: these tools sit on developer laptops full of cloud and repo credentials, and the agent's own trust prompt is the only control — a model-level sandbox bypass plus an unpatched one-click whole-disk read is a supply-chain breach starter kit.
Action: for Codex/VS Code, Weizman advises pulling each machine's trusted-projects list from the config and auditing every HTML file in those projects for the exploit pattern in the technical write-up; treat Workspace Trust as advisory, not a boundary.

## Attacks and campaigns

**319 Chrome extensions, 13.4 million installs: a search-hijacking network that can flip to phishing on command (report published today, Oct 29)**
Socket researcher John Tuckner published an expansion of his April 2025 study today: 319 Chrome Web Store extensions with a combined 13.4 million reported installs — PDF converters, "safe search" and AI-search tools from a handful of organized operators — replace the default search engine via chrome_settings_overrides and funnel every query through operator-controlled proxies to harvest Bing/Yahoo syndication payouts. Some need no code at all beyond a manifest; the biggest active clusters are "Bing-Search" (37 extensions, 2.2M users) and "SecuryBrowse" (58 extensions, 4.9M users), all unlisted in the store and promoted through shady ads. Tuckner's core warning: the proxy chooses each destination at request time (one extension sent six identical searches to four different endpoints), so the same pipes can serve phishing or malicious downloads instantly without any extension update. Most were removed from the Web Store at publication, but new ones keep appearing.
Why it matters: it's a dormant redirection fleet inside the official store — ad fraud today is the watering hole, and the operator can weaponize 13.4 million installed bases with zero further code review.
Action: uninstall any extension on Socket's list, run a full AV scan, and avoid ad-promoted browser tools from unknown publishers.

**BAE Systems: Bankruptcy Noticing Center restored, "no data extracted, no PII breached" (statement today, Oct 29)**
BAE Systems told SecurityWeek today that it has resumed operations of the federal judiciary's Bankruptcy Noticing Center (BNC) — the notice channel for every US bankruptcy court, dark since about Oct 9 — and that "No other systems were affected. No data was extracted. There was no breach of any PII." The Administrative Office of the U.S. Courts confirmed BAE resolved the incident on Oct 27; court logs show notices restarted Oct 26, clearing oldest first, and the Judicial Conference had declared a Bankruptcy Rules emergency on Oct 22 letting judges roll back deadlines. The cause is still unexplained — neither BAE nor the judiciary has said whether it was an attack at all — and no cybercrime group has claimed it.
Why it matters: a two-week outage of the judiciary's notice pipeline with no public root cause is a supply-chain risk statement in itself; "no PII breached" from the contractor whose systems were hit is not an independent verification.
Action: bankruptcy practitioners should keep verifying deadline relief under the Oct 22 emergency declaration; orgs using BAE-hosted judiciary-adjacent services should watch for an after-action disclosure.

## Defensive tools and advisories

**Microsoft resolves the Remote Desktop vs Administrator protection breakage via KB5127936 (fixed status confirmed this week; coverage today, Oct 29)**
Microsoft has fixed the known issue that blocked non-admin Remote Desktop connections (error 0xC000000D) on Windows 11 24H2/25H2/26H1/26H2 hosts when Administrator protection is enabled — the issue Microsoft acknowledged Oct 13 after the KB5124010 September preview, and which bit enterprise-managed RDP hosts where security baselines now enable Administrator protection by default with October updates. The resolution shipped with the KB5127936 preview cumulative update released Oct 28 (41 changes total); Release Health now marks it fixed "by Windows updates released October 28, 2026 (KB5127936), and later." A workaround for admins who won't take the preview: disable Administrator protection by resetting the UAC "Type Of Admin Approval Mode" policy via Intune or Group Policy.
Why it matters: this is the second RDS/Remote-Desktop regression from recent preview updates in six weeks (after September's emergency OOB fixes for Windows Server RDS) — treat preview-channel rollouts to RDS/RDP hosts as a managed risk, not a default.
Action: install KB5127936 (or next month's Patch Tuesday cumulative) on affected RDP hosts; otherwise apply the UAC policy workaround with compensating monitoring.
