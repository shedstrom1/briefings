## Vulnerabilities and patches

**GitLab emergency-patches a CVSS 10.0 unauthenticated RCE in CI/CD (CVE-2026-97229).** Event date: October 12. GitLab released an ad-hoc critical patch — versions 19.4.2, 19.3.5 and 19.2.8 — for an integer overflow in the CI/CD Regular Expression Compiler. An unauthenticated attacker can execute arbitrary code on the GitLab server via a specially crafted regular expression in a CI/CD configuration; GitLab rates it CVSS 10.0 (vector with scope change, network-exploitable, no privileges or user interaction). The same batch fixed 23 other flaws, including a CVSS 8.7 XSS in syntax highlighting (CVE-2026-92883) and a high-severity prompt-injection issue in the Duo Agent Platform. GitLab.com is already patched; GitLab Dedicated needs no action.
*Why it matters:* GitLab self-managed instances are prime targets for supply-chain and espionage operations, and a no-credential RCE on the code-hosting itself puts every repository, pipeline secret and artifact in reach. Public exploit details are withheld for 90 days, which buys a patch window but not immunity.
*Action:* GitLab urges all self-managed installations on 19.2 before 19.2.8, 19.3 before 19.3.5, or 19.4 before 19.4.2 to "upgrade to one of these versions immediately"; single-node upgrades incur downtime.

**Bricksforge WordPress plugin flaw under active exploitation (CVE-2026-85097).** Event date: exploitation attempts since October 7; disclosed by Patchstack October 12. The Bricksforge add-on (used by roughly 6,000 sites per Patchstack) trusted client-supplied file metadata during form submission, letting an attacker grab a nonce from an unauthenticated AJAX endpoint, upload a GIF/PHP polyglot, and get arbitrary PHP executed. Versions up to 3.1.8.9 are affected; fixed in 3.1.8.10 (users should move to 4.0.1). Patchstack observed 63 source IPs, including a burst where 44 IPs sent identical payloads within seconds, plus probes using alternate PHP extensions (.php5, .phtml), case tricks and URL-encoded extensions. Severity is published as CVSS 10.0 by The Hacker News/Patchstack; SecurityWeek cites 9.8 — treat both maximum-severity ratings as a signal to patch immediately. The same coverage details active XSS abuse of WPC Product Bundles for WooCommerce (CVE-2026-93836, CVSS 7.1) and Ninja Forms (CVE-2026-94504, CVSS 7.1) dropping a browser-side implant that installs backdoor plugins and hidden admin accounts.
*Why it matters:* WordPress plugin flaws are commodity intrusion volume — automated kits weaponize them within hours, and the hidden-admin/magic-login persistence survives the plugin update itself.
*Action:* Update to Bricksforge 4.0.1 / WPC Product Bundles 8.6.7 / Ninja Forms 3.15.4, then audit — patching does not evict an existing implant. Review form-submission requests carrying "temporaryFileUploads", unexpected PHP under /wp-content/uploads/bricksforge/tmp/, hidden admins via direct database queries, and the mu-plugins directory.

**SonicWall SMA1000 CVSS 10.0 SSRF hit with 135 exploitation attempts within days of the patch (CVE-2026-102255).** Event dates: attempts first detected October 8; exploitation data published October 12–13. A pre-authentication SSRF in the SMA 1000 Work Place interface lets a remote attacker make the appliance issue requests on their behalf and reach internal functionality. SonicWall shipped hotfixes October 6 (12.4.3-03670, 12.5.0-03082) saying then there was "no evidence" of exploitation; Defused Cyber and Previdian detected attempts starting October 8, and Previdian recorded 135 attempts from two U.S.-located IPs. SonicWall had not updated its advisory to reflect exploitation as of The Hacker News' publication. The same notice fixed three authenticated flaws (CVE-2026-102256 command injection, CVE-2026-102257 Zip Slip, CVE-2026-102258 stored XSS).
*Why it matters:* This appliance line was weaponized as zero-days in June 2026 (UTA0533's web shells, credential and TOTP-seed theft, lateral movement into internal networks). Edge devices with no login barrier and a history of live attacks are top-priority patch targets, and the attack-vs-patch gap here was 48 hours.
*Action:* Apply the platform-hotfixes now on SMA1000 6210/7210/8200v (SMA 100 and firewall SSL-VPN are excluded). No workaround exists; hunt for anomalous appliance-originated internal requests.

**"SlugFest": npm Trusted Publishing flaw left 1,500+ packages one repository-name claim away from takeover.** Event dates: disclosed October 13; GitHub's fix shipped October 2. Bloom Security found that npm's Trusted Publishing validated trusted publishers by the human-readable GitHub "slug" (owner/repo) instead of the immutable numeric repository ID carried in the OIDC token. When a maintainer renamed, transferred or deleted the bound repository, the slug freed — anyone could recreate it, add a workflow file with the matching filename, and receive a publish credential for a package they did not own, with no stolen credentials and a valid provenance attestation naming the attacker's repository. Over 1,500 packages (10M+ total downloads, 1M+ monthly; one alone 200K+/month) were exposed, including security scanners, authentication tools and crypto packages. Bloom reported it via HackerOne June 6; GitHub validated June 9 and, per Bloom, went silent after July 8. No CVE/CVSS assigned by sources — severity per the researchers' demonstration; no known in-the-wild abuse.
*Why it matters:* Trusted Publishing is the credentialless CI publishing backbone of the npm ecosystem, and a hijacked release carrying valid provenance sails past the checks teams use to trust packages. Bloom measured AI coding agents installing roughly 70 packages per endpoint monthly (about 350 on developer machines): a poisoned package "only needs to be the package an agent chooses," and postinstall code runs automatically.
*Action:* Maintainers: run `npm trust list`, confirm each bound repository still resolves under your control, delete and recreate bindings for renamed/transferred repos, and unbind before deleting a repo. Consumers: verify provenance attestations name the project's real repository. Bloom says npm's GitLab trusted-publishing integration shares the weakness.

## Attacks and campaigns

**Attackers hijacked Danfoss refrigeration controllers, defrosting fridges at hundreds of French supermarkets (up to 50°C).** Event dates: overnight October 11–12 attack; CERT-FR alert and Paris prosecutor inquiry October 12. Attackers took remote control of the central controller running each store's fridges and freezers, triggering automatic defrost. Les Mousquetaires (Intermarché/Netto) reported at least 300 stores (Reuters: about 150) and says affected stores discarded all stock; Carrefour 80 supermarkets; Coopérative U 80 of 2,000; Monoprix about 30; E.Leclerc several via an unnamed supplier. Les Mousquetaires' head expects losses in the tens of millions of euros nationally; Sekoia told Reuters Spain, Portugal, Poland, Germany and Belgium were also affected. CERT-FR confirmed numerous compromises of the AK-SM and AK-SC controller series; Danfoss says most hit units were end-of-life models (AK-SM 800, EOL May 2021; AK-SC 355, phased out 2016) that receive no security updates, though some current AK-SM 800A units ran outdated firmware. Researchers have long flagged exposure: Claroty documented an auth-bypass chain (CVE-2025-41450/41451/41452) in the 800A last year, and on Monday Predicta Lab's Baptiste Robert counted 2,752 exposed Danfoss systems (1,590 in France) with Shodan tracking 4,500+. No attribution, no named vulnerability, and as of October 13 CERT-FR had published no IOCs and Danfoss no advisory.
*Why it matters:* This is physical-effect OT sabotage against cold-chain infrastructure — food destruction and small fires, weaponizing end-of-life controllers whose "patch" option doesn't exist. It's also a template: internet-exposed facility-management devices with vendor remote-access paths.
*Action:* CERT-FR: disconnect or IP-filter all AK-SM/AK-SC controllers now (internet-exposed management interfaces violate guidance); on suspected compromise, restrict access to service providers, factory-reset, apply any fixes, rotate secrets, review accounts, fully reconfigure. Owners of EOL units: plan replacement; keep AK-SM 800A firmware at the latest 5.3.x package (note the 3.x→4.x→5.x path and no downgrade from 5.3.x).

**Ahold Delhaize takes systems offline across its retail empire after a cybersecurity incident.** Event date: October 12 company statement (08:29 Amsterdam). The world's largest food-retail group by footprint — 9,400+ stores, ~400,000 employees, ~$104B annual sales under Albert Heijn, Delhaize, Stop & Shop, Food Lion, bol and others — said teams are assessing and mitigating and "taking some systems offline to help protect them," with stores open. In practice, Stop & Shop staff couldn't reach schedules and pay stubs, a Food Lion internal memo flagged inability to "shop, stage, or hand off orders," and websites/apps/customer-service platforms were down for Albert Heijn, Etos, Gall & Gall (NL) and Delhaize (BE). The company declined to say whether encryption was involved or whether corporate and store systems were both hit. This follows the November 2024 attack in which INC Ransom stole data of over 2.2 million individuals. The same week, The Register's security index reported UK fashion group TFG London (Hobbs, Whistles) also took IT systems offline after a cyberattack with order delays (article could not be fetched — see coverage notes).
*Why it matters:* Deliberate disconnect-and-contain at this scale signals something active enough to justify taking revenue systems down blind — and the pattern of simultaneous retail incidents suggests grocers/fashion remain a target cluster for both e-commerce fraud-adjacent intrusion and ransomware pre-staging.
*Action:* Watch for customer-data exposure disclosures from both retailers; expect order-fulfillment and payroll-access disruption in follow-ons. Nothing customer-facing has been confirmed stolen as of the statement.

**Yandex confirms three data centers knocked out by drone strikes; cloud and payments still degraded.** Event date: October 12 confirmation and status updates (strikes occurred October 8 Sasovo, October 9 Kaluga, October 11 Vladimir). Yandex — "Russia's Google" — shut down two facilities completely and is running the third degraded; Yandex Pay remains offline (fintech chief Dima Pirogov promised user funds are safe but gave no restoration timeline), Yandex Cloud is in "emergency mode" at roughly 30% of normal network connectivity per Netblocks on October 11, and search/maps/mail/taxi are partially restored. *Why it matters:* A national cloud's kinetic failure — including a payments platform and the hosting substrate for government and enterprise services — is a live case study in physical-layer DR, and a reminder that "single-region, single-provider" resilience assumptions die in one drone wave.
*Action:* Anyone with Yandex-hosted workloads: activate the vendor's own advice — use alternative sites for hosting and resource redundancy, and validate backups independently given unquantified data-loss risk.

**Preinstalled firmware malware ("Midnight Mimosa") ships in low-cost Android phones across 150+ countries.** Event date: Bitdefender report published by The Hacker News October 13 (Help Net Security also reported October 12). Malware posing as "com.android.system.lite" arrives baked into the system partition of MediaTek-based devices from several low-cost brands, running with system privileges: it installs and uninstalls a rotating set of at least 32 disguised apps, grants itself accessibility/SMS/notification permissions, and loads arbitrary remote code. Monetization runs through dropper apps that masquerade as utilities, overlay invisible windows to inflate ad impressions, and enroll devices as residential-proxy relay nodes; the malware disables Play Protect (by disabling the Play Store app) around each payload install. Bitdefender also found 13 companion apps on Google Play (all now removed) phoning the same infrastructure, observed thousands of unique devices over roughly two years — concentrated in Mexico, then France, Italy, the U.S. and Germany — on devices including counterfeit phones borrowing Samsung and Apple names, some with firmware signed using certificates attributed to Chinese manufacturer Shenzhen Zediel.
*Why it matters:* Every user-facing Android defense assumes the owner is in the loop at install time — the prompt, the store review, Play Protect, uninstallability. Firmware malware voids all of them; cleanup needs firmware-level work most owners cannot do, making this an unpatchable-by-design botnet feeder.
*Action:* Bitdefender: remediation "sits with the vendors and the marketplaces" — buyers of grey-market devices should treat Genuine-Check-style attestation as necessary but insufficient; enterprises should treat unknown-brand Android hardware as an unverified supply chain in BYOD policy.

## Defensive tools and advisories

**Norway issues its largest-ever GDPR fine: $9.6M against Microsoft-owned Xandr over Grindr user data.** Event date: Datatilsynet decision announced October 12. Norway's DPA fined Xandr NOK 92 million for its role as joint controller in Grindr's real-time ad auctions between July 2018 and April 2020, which relayed data exposing sensitive attributes — including sexual orientation — to potentially thousands of bidding companies. The regulator's core finding: Xandr assumed Grindr's consents were valid and never verified them or established its own legal basis. noyb, which co-filed the January 2020 complaint with the Norwegian Consumer Council, called it "a major blow to the online adtech industry." Microsoft (Xandr now operates as Microsoft Advertising) noted the conduct predates its acquisition and says it is reviewing the decision; it has three weeks to appeal.
*Why it matters:* The liability theory — an ad intermediary must validate upstream consent, not inherit it — cuts across every RTB pipeline in adtech, and this is now the DPA's benchmark fine.
*Action:* Ad-tech and publishers relying on third-party consent strings in the EEA: treat intermediary consent-verification obligations as an audit item, not an assumption.
