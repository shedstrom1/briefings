## Attacks and campaigns

**Fireworks AI discloses expanded breach: account and billing data, secrets, datasets and incomplete model weights accessed** — event date: Monday, November 9, 2026 (updated security bulletin; new information)
The AI-inference provider said its October 6 incident (first bulletin October 9, which reported only Fireworks-stored secrets) had wider impact: a third-party cloud provider hosting Fireworks R&D machines was breached on October 23, and on October 24 the unauthorized party used it to reach Fireworks development machines and run an unauthorized workload. Affected data now includes resource metadata, billing and shipping addresses, invoice/payment history, account balance and credit usage — plus, for a limited set of accounts, secrets, datasets and **incomplete model weights**. Fireworks says it never stores payment-card numbers, detected no further successful access after October 25, has revoked/rotated credentials and isolated affected systems with Palo Alto Networks Unit 42 forensics, and has disabled self-serve dataset uploads/downloads for Batch Inference and dataset-based training while investigating. Attribution: "the evidence indicates links to a cybercriminal threat actor group, which is financially motivated and aimed at selling tokens from unauthorized access to Large Language Models to illicit routing gateways" — i.e., LLMjacking, echoing Google GTIG/Mandiant's November 2 report. Severity: Not applicable (breach disclosure; no CVSS published by source).
Why it matters: incomplete model weights are core IP for AI vendors, and this is the first vendor disclosure explicitly tying an intrusion to the LLMjacking economy Google described last week — credentials plus model access are being monetized through illicit routing gateways. It also shows a supply-side path: compromise a third-party cloud provider, pivot to a customer's R&D estate.
Action: Fireworks is notifying impacted customers directly; affected accounts should rotate credentials/API keys and treat billing metadata as exposed for phishing. Anyone running Batch Inference or dataset-based training should expect self-serve dataset transfers to stay disabled.

## Defensive tools and advisories

**ClickHouse Security enters Private Preview — agentic SIEM built on RunReveal + ClickHouse Cloud** — event date: Monday, November 9, 2026
The ClickHouse/RunReveal team announced ClickHouse Security, a "battery-included" agentic SIEM that provisions security schemas and views on your own ClickHouse Cloud service. Built-in agents cover alert triage, detection tuning/generation and threat hunting; custom agentic workflows via MCP server, API, CLI and Slack bot; 100+ first-party cloud/identity/SaaS connectors with pre-storage pipelines; detections as SQL or streaming Sigma rules managed as code with MITRE ATT&CK mapping per finding. Free during preview (you pay ClickHouse Cloud compute/storage); GA pricing TBD; RunReveal's multi-tenant cluster option is being retired in favor of per-customer services. Severity: N/A (product release).
Why it matters: another credible entrant normalizing security data directly inside a general-purpose analytics database — and another agent-first SOC product (triage/hunting as agent workloads), consistent with this month's agent-runtime-security wave.
Action: if you run ClickHouse Cloud, the preview requires no separate deployment — request access via the form and trial detection-as-code against existing services.
Source: "Introducing ClickHouse Security in Private Preview, built on RunReveal," blog.runreveal.com, 09 Nov 2026 — https://blog.runreveal.com/introducing-clickhouse-security-in-private-preview-built-on-runreveal/
