## Vulnerabilities and patches

### Update on previously reported: Node.js November security release ships 19 CVEs, nine High
**Event date: November 11, 2026 (builds published 16:44 UTC / 11:44 a.m. ET; pre-alert covered by the 12:20 edition).** The 12:20 edition reported the Node.js security pre-alert listing three flaws (CVE-2026-123863/123864/123865). The actual builds — v26.13.1 "Lithium", v24.22.3 "Krypton", v22.23.5 "Jod", all published at 16:44:03–16:44:25 UTC — fix **19 CVEs**: nine High (HTTP/2 header release on stream removal, nested-parser execution on empty writes, nghttp2-abandoned stream detection, buffer retention during socket writes, three TLS SNI/resumption defects under CVE-2026-123872 including disabling resumption for mTLS with no session-id context, HTTP/2 stream retention, **CVE-2026-126051 remotely reachable TLS server crash**, plus CVE-2026-123874), seven Medium (ALTSVC buffer overflow, SNI-context CA handling, DATA-to-maxSessionMemory accounting, proxy-credential redaction in invalid proxy URL errors, null write request on cancelled stream, https Agent TLS policy isolation) and three Low (permission-model `fs.watch` descendant leak, zlib params callback after destroy, heap-snapshot destination check). The release also bumps brotli to 1.2.1, llhttp to 9.4.4, sqlite to 3.54.1 and undici to 8.12.4.
**Why it matters:** the headline number changed by 6x after the release landed, and the High-severity set is concentrated in the two network-facing subsystems — HTTP/2 and TLS — where Node runs internet-exposed workloads. CVE-2026-126051 (remote TLS server crash) and the SNI/renegotiation family are the ones that justify an out-of-cycle upgrade for public endpoints, and the brotli bump matters for anyone still exposed to the Node2Shell Brotli line.
**Action:** upgrade to 26.13.1 / 24.22.3 / 22.23.5 on all internet-facing Node runtimes; note the release notes carry no in-the-wild exploitation claim.

### Update on previously reported: Git for Windows 2.56.1 closes the recursive-clone RCE left open at Tuesday's cutoff
**Event date: November 10, 2026, 22:13 UTC (5:13 p.m. ET) — seven minutes after the 17:20 edition went out.** The Tuesday edition reported Git 2.56.1 upstream (CVE-2026-111760) with the caveat "Git for Windows unfixed at cutoff". Johannes Schindelin has now published **Git for Windows v2.56.1.windows.1**, addressing CVE-2026-111760 (recursive-clone RCE: an attacker-controlled repo tricks Git into overwriting a submodule gitfile with a symlink pointing at a directory with malicious config or hooks), CVE-2026-113408 (unborn-HEAD path traversal writing refs to unwanted files), CVE-2026-114467 (>2 GPG signatures in a commit message → stack corruption via `git merge` of a crafted tag), CVE-2026-114469 (binary patches that inflate past the ~1 GiB check → out-of-bounds read crash), CVE-2026-114466 and CVE-2026-105437 (merge-buffer size overflow → heap corruption). SHA-256 digests are published per asset (e.g. MinGit-2.54.0.3-64-bit.zip: `abf956f9e8d7f393…`).
**Why it matters:** this closes the Windows gap on a flaw whose trigger is as ordinary as `git clone --recursive` on an untrusted repository — the highest-leverage fix for developer endpoints, and the reason CI runners that clone arbitrary submodules were flagged as exposed.
**Action:** move Windows developer machines and clone-any-repo CI images to Git for Windows 2.56.1 (or MinGit 2.54.0.3 for embedded use) and verify against the published SHA-256 list.
Source: Git for Windows releases, "Git for Windows 2.56.1", published 2026-11-10T22:13:20Z — https://github.com/git-for-windows/git/releases

## Attacks and campaigns

### Update on previously reported: Notion says the Fireworks AI breach exposed customer Notion AI chat transcripts
**Event date: November 11, 2026 (BleepingComputer, 3:54 p.m. ET; underlying Fireworks incidents October 23–24 and early October).** BleepingComputer reports that Notion disclosed that the Fireworks AI compromise **exposed Notion AI chat transcripts** used by the "Insights" analytics feature, in a small number of workspaces. Notion learned of it from a **November 2 Fireworks alert about an exposed dataset it was told contained only synthetic test data**; Notion cut traffic to Fireworks, deleted its data from the vendor's systems and halted training runs by **November 3**, then found on analysis of the dataset Fireworks delivered **November 8** that it contained real AI chat transcripts. Notion stresses the transcripts were **"unattributable"** — not labelled with author or workspace — and contained **no tool-call results**; Insights has been disabled. Notion repeats that **fewer than 1% of users** are affected, points workspace owners at "Security incident review" in the desktop web interface to let members download their own transcripts, advises affected users to **rotate any passwords, API keys or other credentials entered into affected chats**, and says anyone who has not received a notice is most likely outside the impacted subset. The company also highlights that Fireworks had contractually committed to **zero data retention** for Notion data.
**Why it matters:** this is the clearest case yet in the ongoing AI-infra breach saga of inference-vendor compromise reaching *content* rather than just telemetry — and the mitigation is a user-side secret-rotation habit, not a vendor patch. It also extends the exposure timeline: a "synthetic data" alert on November 2 preceded confirmation on November 8 that real customer data was in the dataset.
**Action:** workspace owners should run the Security incident review export, members should rotate any credential ever pasted into Notion AI, and teams using third-party inference providers should re-check contractual retention terms and disable analytics-at-rest features while the Fireworks post-mortem is pending.
Source: BleepingComputer, "Notion says Fireworks breach exposed customer AI chat transcripts", Bill Toulas, November 11, 2026 3:54 p.m. ET — https://www.bleepingcomputer.com/news/security/notion-says-fireworks-breach-exposed-customer-ai-chat-transcripts/

The oss-security post is dated November 11 (12:19 UTC) and the bug is credited to Anthropic's OSS Scanner (ANT-2026-MAPKT6MZ) and Google Cloud's Anthony Weems and Simon Scannell; **no exploitation in the wild and not in CISA KEV** as of catalog version 2026.11.10. - **Unit 42 "The XG Files": Falcon C2 (aka XG / Xiàng Gē) — browser-native C2 plus the Antino implant.** Published **11 Nov 2026 15:00 UTC (10:00 a.m. ET)**, seven minutes before the window opened (the previous editions did not carry it). Falcon runs entirely inside the victim's browser via JavaScript injected directly into **webmail portals and government web applications**, sideloads malicious Chrome extensions, and steals **passwords, emails, session cookies and communications**; it also delivers **Antino**, a Rust implant that uses **Microsoft OneDrive as its C2 channel** (repeated small JSON writes to `antino/heartbeat/`, `antino/antino_upload/`). Unit 42 observed compromise of government entities in **one Middle Eastern and four Southeast Asian countries between March and May 2026** (foreign-affairs, defence, interior, law-enforcement), and notes near-identical URL structures to Trend Micro's January 2026 **PeckBirdy** framework. Detections: developer-mode extensions requesting `<all_urls>`/`debugger`/`tabCapture`/`nativeMessaging`, `Hm_lvt_` cookies on internal apps, unfamiliar `<script>` tags in webmail/ticketing templates, cross-tenant OneDrive OAuth. — https://unit42.paloaltonetworks.com/falcon-c2-browser-compromise/

With root on the hypervisor, operators get a single web panel for persistence, **guest-VM enumeration and power control, snapshot create/delete, VNC enablement relayed through the C2, network pivoting and credential theft** (including reading NTDS.dit and other secrets straight from VM disks). Insikt publishes C2 indicator **45[.]158[.]196[.]141** (TAG-218 GhostFrame C2). Relevance: hypervisor-as-pivot turns one compromised host into fleet-wide access for ransomware crews. — https://www.recordedfuture.com/blog/ghostframe-esxi-implant-settra-ransomware
