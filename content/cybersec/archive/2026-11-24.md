## Vulnerabilities and patches

**Broadcom ships 23-fix VMware advisory with two 9.8 network-to-host ESX RCEs and a second vCenter auth bypass** — event date: Tuesday, Nov 24, 2026 (VMSA-2026-0011).
The update patches 23 CVEs across ESX, vCenter, Workstation, Fusion, Tools and Avi Load Balancer: 4 Critical, 5 High. The headline pair — CVE-2026-123910 (heap out-of-bounds write, reported by CrowdStrike) and CVE-2026-123911 (use-after-free, DEVCORE via ZDI), both CVSSv3 9.8 — sit in the ESX I/O filter service and let "a malicious actor with network access to ESX… execute code on the host." CVE-2026-123903 (9.8) is another authentication bypass in the VMware Directory Service, found independently by three research teams; CVE-2026-123912 (9.3) is a VM escape via the emulated XHCI USB controller that means host code execution on Workstation/Fusion. Broadcom reports no exploitation and lists no workarounds beyond KB463535 for the two ESX 8.0 I/O-filter flaws.
*Why it matters:* Hypervisor compromise hands over every VM on the host at once, and this is the second vCenter directory-service auth bypass in seven days — the last one (CVE-2026-123890) was exploited as a zero-day by ARMORY CASTLE. A same-component repeat, independently found by three teams, suggests the auth path is fragile.
*Action:* Apply immediately (vCenter 9.1.2 / 9.0.2.0300 / 8.0U3m; ESX 9.1.2.0 / 8.0 U3m builds; Cloud Foundation 5.2.5). **ESX 9.0 patches are still pending — restrict network access to ESX management interfaces now**, and keep vCenter/ESX off the internet.

ESX RCE CVE-2026-123910 — Daily CyberSecurity, Nov 24, 2026 (https://securityonline.info/vmware-update-vmsa-2026-0011/); ESX 9.1.2.0 Release Notes citing VMSA-2026-0011 — Broadcom TechDocs, Nov 24, 2026 (https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/release-notes/vmware-cloud-foundation-9-1-2-0-release-notes/esx-9-1-2-0-release-notes.html)

**WHMCS fixes unauthenticated shopping-cart SQL injection that exposed client records and admin hashes** — event date: vendor advisory Nov 23, 2026 (first security-press coverage Nov 24).
WebPros' WHMCS — the billing platform much of the web-hosting industry runs — disclosed CVE-2026-82981 (CVSS 8.7), insufficient input validation in the shopping cart in 9.0.0 and later: anyone who can reach the cart page can pull client personal/support data plus admin account records with password hashes. Two logged-in-client flaws landed in the same batch: CVE-2026-82979 (7.1, cross-customer data read from the Client Area) and CVE-2026-93700 (9.0 CVSS 3.1), an email-campaign flaw letting a client read server config files — including database credentials — and run code. Fixes: 9.1.2 and 9.0.10 (8.13.8 for the 8.x line; 9.1.2 was not yet listed on the 9.1 release-notes page at THN's publication). All three came from one researcher, "alakazamspooon"; no attacks reported; third WHMCS security round of 2026.
*Why it matters:* A pre-auth read primitive in a billing DB yields exactly the data used for follow-on account takeover (customer identity, invoices, admin hashes), and WHMCS installations are themselves trust anchors for thousands of hosts' customer bases.
*Action:* Update immediately to fixed versions. For the email-campaign flaw the advisory demands more than patching: delete every planned/ongoing email campaign (Utilities > Email Campaigns), clear the template cache (System Cleanup), then update — the advisory doesn't explain why, so treat existing campaigns as suspect. WHMCS Cloud sites auto-update.
Sources: CVE-2026-82981 — WHMCS Security Update 2026-11-23 — WebPros help (updated Nov 23, 2026) (https://help.whmcs.com/m/125386/l/2151347-cve-2026-82981-whmcs-security-update-2026-11-23); WHMCS SQL Injection Could Expose Customer Data and Admin Password Hashes without Login — The Hacker News, Nov 24, 2026 03:34 EST (https://thehackernews.com/2026/11/whmcs-sql-injection-flaw-could-expose.html); WHMCS Shopping Cart SQL Injection: Patch Plan — Brandefense, Nov 23, 2026 (https://brandefense.io/security-news/whmcs-shopping-cart-sql-injection-response/)

**WordPress.org blocked six backdoored "WP Connect" plugins — no fix exists; uninstall and treat sites as compromised** — event date: NVD published CVE-2026-135202 Nov 24, 2026.
Wordfence (the CVE's assigning CNA) rates it 9.8 Critical: six plugins — Air WP Sync, WP Sync for Notion, two Contact Form 7 add-ons (Airtable/Notion), Add-on Brevo for Gravity Forms, Orders Sync to Airtable — shipped a release containing an embedded backdoor (CWE-506) in `includes/airwp-online.php`. It beacons site details (URL, PHP/WordPress/OS versions, server user) to `tascredit-pay.com` on every request and every half hour via WP-Cron, with TLS certificate verification disabled, then `eval()`s whatever PHP the server returns — full shell, file read/write, database dumps including password hashes, webshell drop, and hourly persistence. The plugins are closed on WordPress.org; no patched versions exist. How the code got in (compromised developer account vs release pipeline) is not established.
*Why it matters:* Automatic plugin updates — normally good hygiene — installed remote-code execution that phone-homed to a single C2; the unchecked TLS also lets any on-path attacker take the same control. Sites that never noticed anything are already owned.
*Action:* Uninstall (not deactivate) all six plugins; block `tascredit-pay.com` egress; check for `includes/airwp-online.php`, unknown half-hourly cron events, and PHP files under `wp-content/uploads/`; run a full malware scan, rotate WordPress salts, admin/DB credentials and any Airtable/Notion/Brevo API tokens; restore from a backup predating the affected versions if in doubt.
Sources: WordPress: Backdoor in Six WP connect Plugins — CVE-2026-135202 — cveo.tech, Nov 24, 2026 (https://cveo.tech/blog/wordpress-wp-connect-plugins-backdoor-cve-2026-135202-en); CVE-2026-134401…CVE-2026-135202 listing — Tenable CVE DB, Nov 24, 2026 (https://www.tenable.com/cve/CVE-2026-135202); CVE-2026-135202: WordPress Plugin Backdoor RCE Blocked Before Release — Daily CyberSecurity, Nov 24, 2026 00:47 UTC (https://securityonline.info/wordpress-plugin-backdoor-cve-2026-135202/)

**Update on reported events (CISA KEV): Mail Assure SSRF and MONAI Label zero-day added to KEV with a three-day deadline** — event date: Monday, Nov 23, 2026 (CISA alert).
CISA added CVE-2026-134624 (N-able Mail Assure / SpamExperts SSRF, CVSS 9.3, found during the Mail Assure breach investigation — reported in this brief Nov 23) and CVE-2026-133968 (MONAI Label path traversal — reported Nov 23, the flaw autonomously found and exploited by Cairn AI agents against a university server). Both are marked actively exploited; the Nov 23 KEV alert is the first exploitation confirmation for the SSRF. Federal civilian agencies must remediate by **Nov 26** — one of the shortest BOD 26-04 windows on record — with the usual requirement to check whether threat actors compromised systems before patching. Mail Assure is fixed in build 20261121.1943; MONAI Label (≤0.8.5 default config) had no fixed release at disclosure, so restrict exposure.
*Why it matters:* An exploited MONAI Label instance is exactly the "quiet medical-imaging server on the edge" AI-agent attackers are harvesting, and Mail Assure sits in MSP email paths — both are supply-chain-positioned assets.
*Action:* Remediate by Nov 26; Mail Assure customers verify build 20261121.1943 or later; MONAI deployments restrict network access until a fix lands.

## Attacks and campaigns

**Rackspace is killing Rackspace Spot: service wind-down December 8 after the Nov 17 breach** — event date: wind-down notice posted Nov 24, 2026 04:30 UTC (in-window).
Rackspace published a "Service Wind-Down Notice" on the Spot status page: following "the recent security incident," Spot shuts down **Tuesday, December 8 at 5pm CT**, running workloads are terminated, and data is no longer accessible after that. Customers are being sent retrieval instructions and action deadlines; the status page also shows degraded control-plane uptime (~54%) post-incident. Background (footnoted below): attackers used leaked credentials on Nov 17 for ~22 hours, acting as legitimate users to create pods, read Kubernetes Secrets and list nodes/volumes across affected clusters.
*Why it matters:* A provider choosing full wind-down over remediation is an extreme breach-fallout signal for the spot-Kubernetes niche — and a reminder that cluster Secrets behind a shared management plane are one leaked credential from exposure.
*Action:* Affected customers must complete data retrieval and credential rotation by the deadlines in their notices (at latest Dec 8 5pm CT). Everyone who ever used Spot should assume anything stored in cluster Secrets was readable and rotate.

## Defensive tools and advisories

**OpenAI and Cisco launch Shirudo: AI-agent-written eBPF "shields" that block exploits on live, unpatched Linux** — event date: Monday, Nov 23, 2026 (Cisco PR, San Jose; first security-press write-ups Nov 23 evening–Nov 24, in-window; the Nov 23 17:20 edition missed the announcement).
Shirudo is an open-source runtime where AI agents "find a vulnerability, build a shield, and test that it stops the attack without disrupting the service" — small eBPF programs that block the specific vulnerable code path with no reboot. Every shield is cryptographically signed and verified before loading (Linux eBPF verifier plus kernel lockdown; TPM-backed deployment records), operators approve enforcement, and OpenAI demonstrated a Codex-generated shield that blocked a **Java4Shell** attempt against a running Elasticsearch by adding an input check to Java's Base64 decoder — without restarting the JVM. BSD-2 licensed (BPF programs dual BSD/GPL), code at github.com/shirudo-dev/shirudo; a Linux Plumbers Conference walkthrough covers a shield applied to the recent PHP flaw. SecurityWeek's write-up cautions it is not production-ready.
*Why it matters:* In the ARTEX era, time-to-exploit is measured in hours and vendors ship AI-found bugs in batches; a signed, attested, agent-generated compensating-control layer is the industry's first serious attempt to give defenders a kernel-level "virtual patch" pipeline — Cisco's second agent-defense release this month after Project Quarry (reported Oct 28).
*Action:* Not production-grade; pilot the VM quickstart/Isovalent lab on non-critical hosts if you run unpatchable Linux services; watch the Dec 15 webinar.
Sources: OpenAI and Cisco introduce Shirudo — OpenAI blog, Nov 23, 2026 (https://openai.com/index/introducing-shirudo/); Cisco and OpenAI Launch Shirudo, A New Project to Safeguard Agentic AI — Cisco Newsroom, Nov 23, 2026 (https://newsroom.cisco.com/c/r/newsroom/en/us/a/y2026/m11/cisco-and-openai-launch-shirudo-a-new-project-to-safeguard-agentic-ai.html); "Cisco and OpenAI pitch eBPF kernel plugins…" — The Register security feed, Nov 23, 2026 20:46 EST (https://www.theregister.com/security/headlines.atom); "OpenAI, Cisco Unveil Open Source Tool to Shield Unpatched Linux Systems" — SecurityWeek feed, Nov 24, 2026 12:20 UTC (https://www.securityweek.com/feed/)
