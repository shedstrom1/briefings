## Vulnerabilities and patches

**Microsoft November 2026 Patch Tuesday: 1,235 flaws, exploited Outlook zero-day (CVE-2026-124194)** — Event date: November 10, 2026 (release ~early afternoon ET; BC published 2:07 PM ET).
The release fixes a record-setting backlog — 66 Critical (48 RCE), with 536 EoP, 296 RCE, and 142 Edge (Chromium) bugs; ~639 are Windows components. BleepingComputer's 1,235 count excludes 108 flaws Microsoft fixed earlier this month (Entra Device Registration, Mariner, Edge); SecurityWeek counts 1,094. The single confirmed zero-day is CVE-2026-124194, an Outlook spoofing flaw (Microsoft: Moderate, CVSS 6.5) where a specially crafted message file makes Outlook contact an attacker-controlled share without the external-content warning, disclosing the user's NTLMv2 hash for offline cracking and impersonation; it cannot fire from the Preview Pane, and affects Microsoft 365 Apps, Office LTSC 2021/2024. Credits go to researcher "nono" and Benoît Sevens — the latter acknowledgment notes use of Anthropic's Claude. It is also the final update for Windows 11 23H2 Enterprise/Education.
Why it matters: the one actually-exploited bug is Moderate-rated while this month's headline Criticals sit at "Exploitation More Likely" — CVSS-only prioritization once again points teams the wrong way.
Action: deploy November updates, CVE-2026-124194 first for M365/Office estates.

**Fortinet publishes the embargoed AI-discovered advisories; Critical ospfd auth bypass (CVE-2026-126253) headlines the batch** — Event date: November 10, 2026 (advisory publication; patches shipped Oct 21–22).
FortiGuard's PSIRT page posted the monthly batch today — the promised lift of the three-week embargo on flaws found via Fortinet's frontier-AI-assisted testing program (Anthropic Glasswing / OpenAI Daybreak collaboration). Lead item: FG-IR-26-267 / CVE-2026-126253, an unauthenticated Authentication Bypass by Primary Weakness (CWE-305) in the FortiOS and FortiSASE ospf daemon, rated Critical (CVSS not specified on the index). The batch also includes FG-IR-26-229 / CVE-2026-126184 (spoofing-based auth bypass across FortiAnalyzer/Cloud and FortiManager/Cloud), code-injection advisories FG-IR-26-227/-230, and heap overflows in FortiManager/FortiAnalyzer. Fortinet's CISO blog was updated today confirming the linkage to the AI-assisted program.
Why it matters: this is the first large-scale public accounting of what frontier models found in a major edge vendor's core — and internet-facing FortiGate/FortiSASE boxes had three weeks' head start to patch blind.
Action: verify FortiOS 8.0.2 / 7.6.8 / 7.4.13 / 7.2.14 (and matching FortiManager/FortiAnalyzer builds) are actually deployed; hunt on any appliance that was exposed before the hardening release.

**Git fixes recursive-clone code execution (CVE-2026-111760); Git for Windows still unfixed as of Tuesday afternoon** — Event date: November 10, 2026 (THN ~2:30 PM ET).
Git 2.56.1 (plus backports 2.50.2, 2.51.3, 2.52.1, 2.53.1, 2.54.1, 2.55.1) closes six flaws; the headline is an integer truncation in index handling letting an over-long path be written to disk under a shorter, attacker-chosen name of `.git` — replacing a freshly cloned submodule's .git file with a symlink to a folder of malicious hooks, i.e., code execution on `git clone --recursive`. The batch also fixes CVE-2026-113408 (ref-backend path traversal via malicious server), CVE-2026-114467 (multi-signature tag merge corrupts stack memory), CVE-2026-114469 (oversized binary-patch OOB read), CVE-2026-105437 (GitLab-assigned heap overflow via conflict-marker-size — relevant to mergeability checks on hosting servers) and CVE-2026-114466 (fast-import arbitrary file read/write now gated behind --allow-unsafe-features). No CVSS specified by source. GitHub patched github.com/GHES (3.19.15/3.20.11/3.21.9/3.22.4); THN verified no Git for Windows build based on 2.56.1 as of 19:09 UTC.
Why it matters: recursive clone is the default posture of CI, agent tooling and dependency pipelines — a clone-time RCE in Git is a build-farm-wide problem.
Action: upgrade Git on workstations, CI runners and any app bundling Git; until then, do not recursively clone untrusted repositories.

## Attacks and campaigns

**Update on previously reported (Railway env-var breach, ledger 2026-10-21): post-mortem — ~$740K fraudulent AI usage, up to ~100,000 workspaces' secrets decryptable** — Event date: November 10, 2026 (Railway incident report published today; BC 5:20 PM ET).
Railway confirms attackers reached decrypted customer environment variables for at most 1.85% of workspaces (~100,000 — an upper bound, not confirmed theft). The kill chain: an unknown build-infrastructure flaw on Oct 20 (07:28 UTC) escaped filesystem isolation → an over-trusted internal credential let the attacker read 353 build histories and Railway's internal source code → AI agents used the codebase to hunt parallel entry routes → a misconfigured OIDC trust (Oct 21, 03:26 UTC) yielded a cloud credential, SSH key and finally the key-management access that decrypts env vars. Attackers ran "abliterated models" with an ARTEX-like harness (per Wiz) and queried specifically for AI-provider credentials; stolen keys generated ~$740,000 in unauthorized AI usage (LLMjacking), which Railway says it will cover where providers refuse refunds. 1,852 linked-account tokens (GitHub OAuth, AI agent keys) were reset; attacker fully removed Oct 21; no Git repos or customer databases downloaded.
Why it matters: the strongest public anatomy yet of an agentic-attack vs agentic-defense race, and it ties the October "Black October" AI-platform wave to concrete money.
Action: if you ran workloads on Railway in October: rotate all secrets, audit AI-provider billing for Oct 20–22, report fraudulent charges; Railway says users with no notice need no action.

**Nitori, Japan's largest furniture retailer, says 37.62M customer records stolen** — Event date: November 10, 2026 (BC 3:54 PM ET; intrusion mid-October, detected Nov 6).
The "IKEA of Japan" (879 domestic stores, $5.8B revenue) confirmed an attacker accessed a system from roughly mid-October until detection on November 6, potentially exfiltrating up to 37.62 million customer records: membership numbers, names, emails, postal addresses, phone numbers, dates of birth, gender, corporate-member details and online order data. Passwords and credit-card information were not exposed. Nitori blocked access, patched the exploited vulnerabilities, and notified Japan's Personal Information Protection Commission and police; affected customers get direct email/post notice.
Why it matters: Japan's breach wave (JAL, GMO, Sony's ISP, SEGA, Iris Ohyama — all in this ledger) continues; 37.6M is now the year's biggest Japanese retail disclosure and prime phishing ammunition.
Action: Nitori customers — expect phishing; Nitori will never ask for password, card number or PIN by email/phone. Security teams — treat Japanese-retail PII dumps as a sustained BEC/phishing-input indicator through Q4.

## Defensive tools and advisories

**CISA adds six to KEV (BOD 26-04): two new names plus re-listings of the Outlook, Chrome and Barracuda flaws** — Event date: November 10, 2026 (alert released Nov 10, 12:00 UTC; per-CVE due dates not listed in the alert).
The six: CVE-2026-20320 (Cisco BroadWorks XXE — unauthenticated sensitive-file read), CVE-2026-111793 (Openwave Messaging Webtop Media Transcoder, incorrect resource transfer, CVSS 4.3 per CVE trackers), CVE-2026-116606 + CVE-2026-111560 (the Barracuda ESG auth-bypass + OS-command-injection pair, previously rated 9.3/8.6 and confirmed exploited Oct 30), CVE-2026-124194 (this afternoon's Outlook zero-day) and CVE-2026-125350 (Monday's Chrome XML use-after-free, the eighth exploited Chrome bug of 2026). The Barracuda pair matters chained: individually each needs admin-UI reach or admin rights; together on an internet-facing ESG they yield root.
Why it matters: CISA just stamped KEV status on a same-day Microsoft zero-day and a two-day-old Chrome fix — the catalog is tracking exploitation within hours again, and BroadWorks/Openwave show legacy unified-messaging software joining the exploited-in-the-wild set.
Action: federal FCEB remediation clocks started today (BOD 26-04); everyone else: patch Outlook and Chrome now, hunt on any Barracuda ESG whose admin UI was internet-exposed — patching won't evict an intruder — and check whether you still run BroadWorks or Openwave.
