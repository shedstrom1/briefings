## Vulnerabilities and patches

### Xen Orchestra empty-object login token actively exploited; critical advisory and fixes published Nov 10
**Event date: November 10, 2026 (advisory published; exploitation ongoing).** Vates disclosed VSA-2026-062, a Critical-severity flaw in Xen Orchestra / Xen Orchestra Appliance: REST cookie parsing turns `authenticationToken=j:%7B%7D` into `{}`, REST authentication passes that object to the XO token provider without requiring a string, and the token collection returns its **first token**, authenticating the caller as that token's owner. The authenticated `/rest/v0/users/me/authentication_tokens` route then leaks reusable login token IDs. Impact is admin-privilege actions on XO — which the advisory says can escalate to arbitrary code execution on managed pools and **full root takeover of XCP-ng nodes**. Vates names live attacker infrastructure (`91.211.251.112:8001`, plus a Tor rendezvous on port 3333), warns there is **no log entry for successful exploitation**, and gives hunt patterns: HTTP requests containing `authenticationToken=j:%7B%7D` or `authenticationToken=j:{}`, a running VM named `pivot2`, and XCP-ng hosts showing VMs with `hvm_serial: file`. Fixed builds: xo-server 5.213.1 (latest) / 5.211.2 (stable), shipping in Xen Orchestra 6.10.0 / 6.9.1.
*Why it matters:* XO is the control plane for XCP-ng/Citrix-style virtualization estates; one unauthenticated request converts a web-exposed management console into hypervisor root, and the vendor's own detection note — no auth logs on success — means compromise must be hunted, not alerted on.
*Action (from the advisory):* upgrade xo-server; block `91.211.251.112` and the `.onion` C2; add a WAF/reverse-proxy rule for `authenticationToken=j:{}` / `j:%7B%7D`; hunt for `pivot2` VMs and `hvm_serial: file`; then **rotate all Vates VMS passwords and secrets** (proxy, backup, S3, root, user accounts) because configuration exfiltration and credential harvesting cannot be ruled out.
Source: Vates VMS Security Advisories, "VSA-2026-062: Empty-object login token," published/updated 2026-11-10 — https://docs.vates.tech/security-advisories/advisories/2026/vates-sa-2026-062/
Source: Hacker News (story 50438830), "Critical Xen Orchestra authentication bypass is being actively exploited," 2026-11-10 11:29 UTC — https://news.ycombinator.com/item?id=50438830

### SAP November Patch Day: four CVSS 10.0 flaws, two enabling unauthenticated RCE
**Event date: November 10, 2026.** SAP's monthly Security Patch Day closed 35 vulnerabilities, four of which SAP itself rates the maximum CVSS 10.0 and all of which are reachable without credentials or user interaction: CVE-2026-76964 (memory corruption in the NetWeaver AS ABAP Internet Communication Manager), CVE-2026-89126 (the same root cause in SAP Web Dispatcher), CVE-2026-89103 (broken access control in SAP Gateway) and CVE-2026-120017 (SAML2 service provider that, under some configurations, did not verify signatures on incoming assertions). Onapsis — which reported three of the four — tracks the ICM/Web Dispatcher pair as **ICM2SHELL** (heap out-of-bounds write via WebSocket control frames with invalid length fields) and the Gateway bug as **PROXYGATE**, which convinces the gateway that an external attacker is one of the system's own application servers, yielding control as the installation owner. SAP Notes: 3778530, 3778556, 3798345, 3849308.
*Why it matters:* Web Dispatcher sits in front of almost every enterprise SAP deployment, so these are internet-facing pre-auth entry points into ERP estates; CISA has flagged 14 SAP flaws as exploited since November 2021, three of them also used by ransomware groups.
*Action (from Onapsis via The Hacker News):* patch kernel and every Web Dispatcher in one rollout; set `gw/acl_mode_proxy` and confirm `gw/acl_mode=1` with explicit secinfo/reginfo rules; ensure the gateway port (33xx) and ICM ports are unreachable from user networks/the internet; audit all trusted identity providers in transaction SAML2 and review privileged SAML logons. Notes list no workarounds for the SAML2 and Gateway flaws.

### Google patches CVE-2026-125350, its eighth exploited Chrome zero-day of 2026
**Event date: November 9–10, 2026 (Google stable-channel advisory Monday; fix rolling out overnight).** Google fixed nine vulnerabilities including a high-severity **use-after-free in Chrome's XML component**, CVE-2026-125350, reported anonymously on Nov 6; the advisory states "Google is aware that an exploit for CVE-2026-125350 exists in the wild" while keeping bug details restricted. Fixed versions: 157.0.8103.50/.51 (Windows/macOS) and 157.0.8103.50 (Linux). This brings 2026's exploited-Chrome tally to eight, alongside CVE-2026-2441, -3909, -3910, -5281, -11645, -85046 and -87491.
*Why it matters:* Chrome zero-days cluster, and the XML parser is reachable from ordinary web content — an exploit-in-the-wild browser flaw with restricted details is the classic pattern for surveillance- and crimeware-grade drive-by delivery. *Action:* update to 157.0.8103.50/.51 (More → Help → About Google Chrome), relaunch, and force the update through enterprise policy rather than waiting for the days-to-weeks staged rollout.

### Binance warns of iOS container escape "worse_query"; no fix listed in Apple's newest updates
**Event date: November 10, 2026 (Binance security warning).** Binance warned that a sandbox/container escape published on GitHub by researcher **forcequit** on Sunday lets an app read other apps' files on iPhones running iOS 26 and 27 (listed as iOS 26.0–26.7.2 and iOS 27.2, with 27.3 beta also affected), putting seed phrases, private keys and login credentials within reach of malicious apps. The PoC needs an App Group container, which sideloading tools such as AltStore/SideStore create automatically; developer Christoph Kolbicz's WQ Files already uses it to browse, edit and delete other apps' data without a jailbreak or kernel exploit. Neither Binance nor the researcher reports observed attacks, and Apple's iOS 27.2.1 / 26.7.3 updates released Monday do not mention it.
*Why it matters:* it is an unpatched, publicly demonstrated break of app data isolation on the platform most crypto custody apps depend on — and SlowMist's CISO notes it is a container escape rather than a jailbreak, so detections tuned to jailbreak artifacts won't fire.
*Action (from Binance):* delete apps installed from untrusted sources (sideloaded/manually signed), update iOS and all apps, and if compromise is suspected move funds to a new wallet created on a clean device and reset all active login sessions.

## Attacks and campaigns

### ESET: Turla's new "Cereal" toolset turns government Exchange servers into their own C2
**Event date: November 10, 2026 (ESET Research publication).** ESET says the Russia-aligned, FSB-assessed group Turla (Snake) deployed an undocumented modular .NET toolset on Microsoft Exchange servers at two national government organizations — one in Kazakhstan (found Nov 28, 2025) and one in Romania (compromised Dec 23, 2025) — configured to copy out email addressed to or from **NATO and EU** institutions. Main backdoor **CerealNeuron** listens on paths that look like normal OWA/Autodiscover traffic and returns legitimate-looking error pages to anything else, so the victim's own internet-facing Exchange hosts the command channel; commands arrive as purpose-built in-memory .NET assemblies (mailbox pulls, AD queries, LSA-secret extraction, file read/delete), with **CerealHermit** reading encrypted command files from disk as an offline fallback. **CerealBox** avoids registering a transport agent entirely by injecting into `EdgeTransport.exe` and wrapping already-loaded transport-agent handlers — previously undocumented for any malware family — keeping only `.doc`/`.docx`/`.pdf` messages matching hardcoded sender/recipient/subject/attachment lists. Loaders masquerade as `ncobjapi.dll` or `wbemcomn.dll` in `C:\Windows\System32\wbem` or squat in the .NET native-image cache (e.g. `Microsoft.Exchange.Search.Mdb.ni.dll`). ESET could not identify operator IPs; activity surged Jan 15, 2026, the day after the Russian Old New Year.
*Why it matters:* server-side mail collection with no external infrastructure defeats IP/DNS-based blocking and puts diplomatic and military correspondence at risk at the transport layer; ~70% of Turla's post-2022 targets are former Soviet republics or former Soviet-aligned European states.
Source: ESET Research newsroom, "Russia-aligned Turla group uses novel Exchange tool to spy on EU, NATO emails," November 10, 2026 — https://www.eset.com/us/about/newsroom/research/eset-research-turla-cereal-exchange-email-espionage/

### Vanderbilt University responds to BYOD ransomware; gang claims >1M SSNs and full DC takeover
**Event date: November 9, 2026 (university statement 6:52 PM ET posting; BYOD leak-site claim Monday).** Vanderbilt said Monday it is "responding to an active cybersecurity incident that may impact university devices, systems, and cloud-based services," telling students, faculty and staff to **shut down university devices, disconnect from university Wi-Fi** and report pop-ups, altered cloud files, unfamiliar applications or unexpected authentication prompts — and not to troubleshoot themselves. The BYOD ransomware gang claimed the attack on its leak site: "your databases are locked… We have your entire estate and research data. Over 1 Million SSNs, Full Names, Email addresses, Phone Numbers, Student & Employee Records, Full takeover of your DC." BleepingComputer verified a ransom note (`README_BYOD_31.txt`) linking to BYOD's leak site and SESSION contact, plus video of infected machines playing an audio compromise message. Vanderbilt has not confirmed the group or the encryption/theft claims. BYOD is a 2026-era gang with six listings and is the same operator behind the University of New Mexico Health Sciences Center attack.
*Why it matters:* BYOD has moved from opportunistic claims to higher-education targets with credible evidence (verified note and video) and it disables backups as a negotiating lever — "we have all of your data including your backups" is exactly the extortion posture that turns an encrypt-and-exfil into an operational outage.
*Action:* follow the university's instruction to power down rather than self-troubleshoot; for peers of the institution, treat the shutdown guidance as the containment signal it is and verify offline/immutable backup reachability now.

## Defensive tools and advisories

### Update on previously reported (ledger Nov 9, "bossai-taipei-dispatch") — Acronis TRU publishes Cyber Pulse 2026: 575+ malicious OpenClaw skills, LockBit 5.0 ESXi variant
**Event date: November 10, 2026 (report coverage).** Acronis Threat Research Unit's Cyber Pulse 2026 documents **more than 575 malicious OpenClaw "skills"** posing as utilities and delivering trojans, cryptominers and infostealers to Windows and macOS — the agent-supply-chain angle is that skills combine instructions with executable code running under permissions the agent already holds. The same report covers the BOSSAI single-operator/AI-agent stack (10+ models driven over WeChat and LINE), a **LockBit 5.0 ESXi build that shuts down running virtual machines before encrypting them**, an INC encryptor that deletes snapshots, The Gentlemen's EDR-disabling toolset, and the TamperedChef campaign distributing working PDF/manual apps signed with **valid EV certificates** issued through rotating US shell companies. Acronis also notes that of 1.8M endpoints running its own RMM agent, **63.1% had at least one additional remote-management tool** installed — a standing lateral-movement path.
*Why it matters:* the defensive lesson is inventory, not detection: unmanaged second RMM tools, agent skill marketplaces and EV certs from new shell companies are all "legitimate-looking" and are being weaponized ahead of any malware signature.
*Action implied:* enumerate and remove unused remote-management agents, gate agent-skill installation to vetted registries, and treat ESXi hosts as encryption targets (offline/immutable copies of VMFS metadata and snapshots).
Source: Help Net Security, "Over 575 malicious OpenClaw skills delivered malware to Windows and macOS," November 10, 2026 — https://www.helpnetsecurity.com/2026-11-10/acronis-ai-agent-cyberattacks-report/
