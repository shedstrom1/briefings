## Vulnerabilities and patches

### Rails Active Storage: unauthenticated arbitrary file write via crafted ImageMagick uploads (Rails CVSS 9.8; no CVE yet) — event November 4, 2026

Ruby on Rails disclosed and fixed a critical flaw (GHSA-f3w6-w445-fwh9) in Active Storage: because ImageMagick selects its format handler (coder) from file *content*, and Active Storage imposes no coder limits on uploads, an unauthenticated attacker can make the server's ImageMagick read and write arbitrary files — a crafted SVG reaches the MSL scripting coder, which writes files named inside it. Attaching the upload is enough; the app does not need to generate variants or previews. Apps storing uploads with Active Storage's Disk service also expose arbitrary *reads*, which typically yield `secret_key_base` and stored credentials — enabling RCE or lateral movement. Rails rates the flaw 9.8/10; it has no CVE identifier. The same releases (8.1.4.1 and 8.0.5.2, 21 security issues total) fix a second Active Storage flaw (GHSA-v924-7rp8-4mxh, Rails-rated CVSS 8.8) where temp filenames kept the upload's extension, letting an attacker choose the decoder. Exposure requires all three of: ImageMagick as the Active Storage processor (`:mini_magick` — the default for apps on `load_defaults` 6.1 or earlier), a server ImageMagick policy that doesn't already block the coders (Debian/Ubuntu stock policies don't), and untrusted-user uploads. Rails said one attack chain was reported to it (via HackerOne, by RyotaK of GMO Flatt Security) but does not assume it is the only one; the advisory does not say whether it has been exploited. Apps on release series older than 8.0 get no fixed versions, and Rails 8.0's security-fix window closes November 7, 2026.

**Why it matters:** This is the default configuration for a huge installed base of legacy Rails apps (mini_magick was the default processor through 6.1), the attack is unauthenticated and triggered by a bare file attachment, and the read primitive exposes the app's master secret — the keys to session forgery and every credential the app holds. The fix also ships a hardened ImageMagick policy, which Rails warns silently fails to load in apps that override `MiniMagick.cli_env`/`cli_prefix` or install their own shell.

**Action:** Upgrade to Rails 8.1.4.1 or 8.0.5.2 plus mini_magick ≥5.1; verify the shipped policy loads (`bin/rails runner 'puts MiniMagick.identify { |i| i.list "policy" }'`); if you can't upgrade yet, copy the shipped `policy.xml` rules into the system ImageMagick policy — at minimum block the MSL coder, Ghostscript-backed coders and the `gs` delegate; if you use the Disk service, rotate `secret_key_base`, the master key, credentials.yml.enc contents, and storage/database credentials.

## Attacks and campaigns

### APT29 mobile watering-hole campaign serves zero-click n-day chains to iOS/Android via poisoned sites and a compromised analytics tracker — Sekoia disclosure, November 4, 2026

Sekoia's TDR team published a full report on a large-scale watering-hole campaign, uncovered in mid-October 2026, using three infection vectors: direct JavaScript injection into legitimate websites (a Ukrainian gas-production company, a major US chemical-industry trade association, a far-right European political party, a Bulgarian military-related site), adversary-in-the-middle lookalike domains (clones of America250 and the Raffles London at The OWO), and a one-week supply-chain compromise of Ukrainian web-analytics service Plerdy's SEO tracker, which thousands of sites — mostly Ukrainian — loaded between August 27 and September 3. All vectors drop a fingerprinter script (e.g., `static.flux-telemetry[.]com`) that profiles device/browser, after which the delivery host serves platform-specific n-day exploit chains with no user interaction. The iOS chains include DarkSword (suspected commercial-surveillance-vendor kit, CVE-2025-43529, uploaded to VirusTotal in September 2026); final payloads exfiltrate cookies or full device data from iOS, and Chrome data plus Wi-Fi passwords from Android. No payload established persistence — a reboot halts activity until the user revisits a compromised site. Sekoia attributes the operation with moderate-to-high confidence to APT29 (Midnight Blizzard/Cozy Bear, SVR), citing infrastructure overlap (delivery/exfil IPs 109.104.106.107, 95.133.231.28, 195.58.140.105), victimology and parallels to prior APT29 watering holes, and says it is coordinating with national CERTs. Campaign severity: Not specified by source. All exploited flaws are patched by Apple and Google, including older iOS lines.

**Why it matters:** It shows a top-tier SVR collection actor commoditizing leaked/commercial exploit technology (DarkSword, previously seen in infostealer use) at watering-hole scale, weaponizing a third-party analytics dependency the way earlier actors weaponized ad networks — and the stolen artifacts (session cookies, Wi-Fi keys, device data) are exactly what enables follow-on account takeover against Ukrainian and Western targets.

**Action:** Ensure all mobile devices run the latest Apple/Google security updates; hunt for the listed domains/IPs and stage-1 hashes in proxy/DNS logs; audit exposure to the Plerdy tracker (Aug 27–Sep 3) and any of the named compromised portals.

- Source: BleepingComputer, Bill Toulas, November 4, 2026 04:39 AM ET — https://www.bleepingcomputer.com/news/security/hackers-use-n-day-exploits-in-zero-click-attacks-on-ios-android-devices/

### ESET: China-aligned SlippyNunchucks hijacks Sogou Input Method DNS to deploy DarkVigil implant — ESET Research, November 4, 2026

ESET Research published (BRATISLAVA/MONTREAL, November 4, 2026) the analysis of a DNS-hijacking operation attributed to China-aligned actor SlippyNunchucks (active since at least September 15, 2023). The group abuses the insecure HTTP communications in the Windows versions of Tencent's Sogou Input Method: its "EdgeStepper" component redirects DNS queries to a malicious resolver that, when the queried domain is update-related (for example `info.pinyin.sogou.com`), answers with the IP of a hijacking node that delivers the DarkVigil (aka FDMTP) implant. The surveillance campaign, observed from July 1, 2026, targeted organizations and Chinese-speaking individuals in Hong Kong, Thailand, Japan, Vietnam, Oman and Sri Lanka; ESET says DarkVigil implants are typically deployed by abusing popular Chinese applications — Sogou Input Method, QuickFox, QingTalk, MiYunChat, SoftCam and tawk.to among them. Severity: Not specified by source.

**Why it matters:** It turns a trusted, auto-updating utility used by Chinese-speaking populations worldwide into a state-adjacent targeting channel — victims' machines reach out over plain HTTP, so the hijack needs no user interaction and no vulnerable client bug, only a man-on-the-side position in the DNS path. Enterprises with Chinese-speaking staff running Sogou on Windows should assume the update channel is an adversary neighborhood.

**Action:** Block/monitor insecure HTTP update traffic for Sogou and the other named applications, enforce DNS-over-TLS/HTTPS where possible, and hunt for DarkVigil/FDMTP indicators per ESET's report.
