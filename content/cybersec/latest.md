## Vulnerabilities and patches

**Arista patches actively exploited VeloCloud Orchestrator zero-day (CVSS 9.9)** — *Event date: October 22, 2026*
Arista published Security Advisory 0199 for CVE-2026-114625, a SQL-injection flaw in VeloCloud Orchestrator (VCO) On-Prem, the central management system for VeloCloud SD-WAN (formerly VMware SD-WAN, acquired from Broadcom). Anyone with a valid login — down to the lowest built-in Enterprise Read Only role — can escalate to operator, i.e. local-superuser control of the orchestrator, and potentially affect the VCO host itself. VCO is exposed by default and no VCO setting prevents that exposure. This is the third VCO flaw Arista has reported as exploited since late July (after CVE-2026-16812 in July and CVE-2026-93952 in September) and the first requiring a login. Orchestrators on the trains patched for the September flaw are still vulnerable, because those builds predate today's fixes. Arista published two attacking IPs: 74.82.197[.]86 and 38.54.50[.]151.
- **Why it matters:** the orchestrator holds credentials and policy for every managed Edge; a compromised VCO effectively owns the WAN of every customer tenant. The read-only-foothold requirement lowers urgency slightly versus the earlier unauthenticated flaws, but read-only and partner accounts are exactly what attackers phish or recycle.
- **Action:** upgrade on-prem VCO to 5.2.3.18 / 6.1.3.10 / 6.4.2.12 (Hosted/Dedicated already patched); block the two IOCs, restrict VCO web UI to trusted admin networks, and audit recent admin activity plus web-access logs for SQLi-shaped URL components. Note 6.1 still has no fixed release listed for September's CVE-2026-93952.
- Sources: Arista Security Advisory 0199 (Oct 22, 2026) — https://www.arista.com/en/support/advisories-notices/security-advisory/24838-security-advisory-0199 ; The Hacker News, "Arista Warns of Critical VeloCloud SQL Injection Zero-Day Exploited in Attacks" (Oct 22, 2026) — https://thehackernews.com/2026/10/arista-warns-of-critical-velocloud-sql.html ; BleepingComputer, Sergiu Gatlan (Oct 22, 2026, 1:18 PM ET) — https://www.bleepingcomputer.com/news/security/arista-patches-new-velocloud-orchestrator-zero-day-exploited-in-attacks/

**ZDI publicly discloses two unpatched CVSS 9.0 KSMBD kernel RCEs** — *Event date: October 22, 2026 (disclosure)*
Trend Micro's Zero Day Initiative posted details of five Linux kernel reports to public mailing lists, and the two most serious sit in KSMBD, the in-kernel SMB server. ZDI-CAN-33774 (CVSS 9.0) is a pre-authentication race in SMB1→SMB2 handler dispatch — a burst of short SMB1 packets followed by an SMB2 packet in the same TCP write makes workers read past a buffer's end; any KSMBD install listening on 445 is exposed. ZDI-CAN-33549 (CVSS 9.0) is an integer underflow in the SMB Direct/RDMA path. Neither has a named fix in mainline or linux-next, and neither has a CVE (the kernel project assigns CVEs only once a stable fix exists); Phoronix reports SMB Direct maintainer Stefan Metzmacher has submitted a fix for 33549 targeting the next development cycle. The three other reports cover skbuff (LPE 7.8), vmwgfx (LPE 8.8) and nvmet (info-disclosure 8.6). Stable maintainer Greg Kroah-Hartman publicly chided ZDI for copying public lists without patches; the findings are credited to TrendAI, Trend Micro's AI scanner.
- **Why it matters:** a pre-auth 9.0 in a kernel SMB server that distros ship (KSMBD is opt-in but common in NAS/Samba-alternative builds) is a worm-shaped gap, and the public-listing-then-fix gap means attackers have the details today. Check `lsmod | grep ksmbd` / `systemctl status ksmbd` — RHEL does not ship KSMBD by default.
- **Action:** if KSMBD is loaded, firewall 445 to trusted clients now and treat the module as exposed; watch for Metzmacher's SMB Direct patch landing in the next cycle.
- Sources: The Hacker News, "Two CVSS 9.0 Linux KSMBD RCE Flaws Disclosed on Public Mailing Lists Before Kernel Fixes" (Oct 22, 2026) — https://thehackernews.com/2026/10/two-cvss-90-linux-ksmbd-rce-flaws.html ; Threat Landscape (Oct 22, 2026) — https://threatlandscape.io/blog/ksmbd-zdi-can-33774-33549-unpatched-rce ; ZDI advisory page — https://www.zerodayinitiative.com/advisories/ZDI-26-684/

**Update on previously reported — LiteLLM release-pipeline attack: official advisory pins Docker/GHCR compromise window** (ledger: LiteLLM 1.107.0 PyPI trojan, Oct 21; root-cause update, Oct 22 07:00) — *Event date: advisory live October 22, 2026*
LiteLLM's formal incident post ("Contained: Oct 21, 2026") and BleepingComputer's 3:12 PM ET story add the full distribution scope: the malicious build went to PyPI **and** the `v1.107.0`, `latest`, `main-latest` and `main-stable` tags on both Docker Hub and GHCR. Impacted pulls: pip between 11:39–13:23 UTC Oct 21, and any unpinned Docker/GHCR tag pull between 11:46–14:20 UTC. The company says threat actors defeated "multiple independent security controls," and the payload adds an hourly GitHub dead-drop remote-code backdoor to the credential stealer. BleepingComputer's update emphasizes the info-stealer (credentials, secrets, environment variables) angle.
- **Why it matters:** teams that scrubbed PyPI at the first alert but left `latest:` Docker images running in CI are still exposed. Pin digests, rotate anything those containers could touch, and treat the pull windows as the blast radius.
