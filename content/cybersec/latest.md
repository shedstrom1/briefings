## Attacks and campaigns

**Microsoft: China-state Storm-0940 ran the ConnectWise supply-chain compromise with agentic-AI tool ARTEX** — *Update on previously reported (ledger: ConnectWise/SkyKick credential abuse, Oct 18–20)*
Event date: October 21–22, 2026 (Microsoft Security Blog disclosure; outlets followed overnight). Microsoft's Threat Intelligence team assessed that Storm-0940, active since at least 2021, used the Go-based ARTEX agentic penetration-testing framework to automate scanning, password spraying and OAuth application abuse after obtaining the identities of multiple ConnectWise cloud applications on October 15. The agent-driven campaign attempted sign-ins to more than 2,250 Microsoft 365 tenants — peaking at 2,900 attempts per minute — and in multiple cases reached privileged access to organizational cloud infrastructure in under three hours; a cross-tenant spray from 144.172.64[.]99 between October 10–14 generated over 151,000 failed logons. Microsoft stressed app-credential modifications made by the agents can persist as a backdoor even after the compromised application is remediated, and ConnectWise said services are still being restored in phases.
**Why it matters:** This is the first major nation-state campaign documented as AI-agent-accelerated end-to-end at supply-chain scale — the compression of dwell time to sub-three-hour compromise windows outpaces human SOC response cadences, and the persistence via injected application credentials survives vendor-side cleanup.
**Action:** Microsoft says customers should review service-principal sign-ins, investigate unexpected application credential or privilege changes, apply ConnectWise's published containment guidance, and preserve evidence; Defender XDR hunting queries for the IOCs are published.
Source: Microsoft Security Blog, "AI-driven, large-scale nation-state campaign using ARTEX enables supply chain compromise," Oct 21, 2026 — https://www.microsoft.com/en-us/security/blog/2026/10/21/storm-0940-uses-artex-agentic-ai-connectwise-supply-chain-compromise/

**Railway warns intruder may have accessed decrypted customer environment variables; crypto already drained** — *Event date: Wednesday, October 21, 2026 (disclosed Wednesday evening)*
Platform-as-a-service provider Railway disclosed "anomalous activity" in the systems that store customer environment variables, finding an unauthorized third party may have accessed encrypted variables — and obtained the decrypted contents for some — in an incident it says likely targets platform companies en route to AI inference providers. The impact is limited to an unquantified "subset of users"; Railway has rotated all bucket credentials, invalidated Railway API tokens, and is re-enabling builds workspace-tier by workspace-tier. Researcher Taylor Monahan (@tayvano_) reports the attacker address 0xd9773325282874d18cb83f1fe50f14c39750b2ee has already drained cryptocurrency wallets whose private keys were stored on Railway, with the first theft at 7:36 p.m. — at least two hours before Railway's disclosure.
**Why it matters:** Env-var stores are the soft underbelly of PaaS: one store compromise yields API keys, DB credentials and registry tokens across many tenants, and the two-hour gap between theft and disclosure shows response is already reactive. Combined with the LiteLLM story below, platform-level secret stores are the month's recurring breach vector.
**Action:** Rotate all environment variables, API keys and private-registry credentials held in Railway without waiting for an individual notification, and review service logs for unusual activity.

**ESET: Sandworm handoff from UAC-0099 powered data-wipe at Ukrainian grain-logistics firm; first documented Yggdrasil C2** — *Event date: Thursday, October 22, 2026 (ESET report published Thursday)*
ESET reported that Russian-aligned espionage group UAC-0099 phished its way into an unnamed Ukrainian grain logistics company in July 2025, planted the MatchWok backdoor plus a previously unknown remote-access tool dubbed MythicRatatoskr, then handed access to GRU-linked Sandworm, which executed a data-wiping attack in September. Malware communicated over Yggdrasil, a decentralized encrypted network — "the first documented case of Yggdrasil being abused in this way by a state-aligned threat actor," ESET said, warning hubless C2 is resilient to takedown. A Linux variant of the backdoor may also exist.
**Why it matters:** Deliberate destruction against agricultural logistics extends Sandworm's anti-Ukraine playbook into food-supply chains, and decentralized-network C2 removes the single infrastructure node defenders traditionally seize.
Source: The Record (Recorded Future News), "Russian hackers teamed up to wipe data at Ukrainian grain firm," Oct 22, 2026 — https://therecord.media/ukraine-hackers-russia-grain-sandworm

**LiteLLM advisory: trojaned 1.107.0 pushed via leaked GitHub CLI tokens in its own AI-gateway logs** — *Update on previously reported (ledger: LiteLLM 1.107.0 PyPI/Docker trojan, Oct 21)*
Event date: October 21–22, 2026 (LiteLLM advisory published Wednesday). LiteLLM disclosed that attackers leveraged three developers' GitHub CLI credentials — one able to run workflows — after the project temporarily expanded release permissions on October 19, using an org-owner token to disable branch protection, force-push, and run the release pipeline pointed at lookalike repo "Berri-AI/litellm" to sign and publish poisoned artifacts. Impacted users are precisely time-boxed: pip installs of unpinned LiteLLM between 11:39 and 13:23 UTC, and Docker pulls of v1.107.0/latest/main tags between 11:46 and 14:20 UTC on October 21. The stealer ("privcollect," exfil to litellm[.]dev/healthcheck) plus an hourly GitHub dead-drop RAT ran via a cook.pth/sitestcustomize.py pair that Wiz called the first documented in-the-wild use of that dual technique — and Wiz observed the attacker validating stolen AWS instance-role credentials from 168.100.8[.]57 and 165.227.201[.]8 between 16:20–17:01 UTC, probing Bedrock model lists "consistent with LLMjacking."
**Why it matters:** Root cause is the AI supply chain itself: LiteLLM observed that Claude Code can embed a user's GitHub CLI OAuth token into response bodies, which then landed logged in LiteLLM's gateway — developers' own tooling leaked the keys that signed the release. Despite post-March hardening (private release repo, immutable signed tags), a two-day permission expansion defeated it all.
**Action:** Remove 1.107.0, isolate hosts that installed it, hunt for cook.pth/sitecustomize.py artifacts, block litellm[.]dev, investigate any /codepy execution, and rotate every reachable credential; JFrog: "a clean source repository tells you little about the artifact you actually install."

## Vulnerabilities and patches

**Amazon: PHP2Shell was exploited four days before disclosure; now "broadly exploited in the wild" — six IOCs published** — *Update on previously reported (ledger: PHP2Shell CVE-2026-109618/109619 leak + emergency release, Oct 21)*
Event date: October 21–22, 2026 (Amazon Threat Intelligence post; THN follow Oct 22). Amazon's MadPot honeypots recorded a PHP2Shell exploit attempt on October 17 — while both CVEs (CVSS v4.0 9.2) were still under embargo — from 103.216.220[.]92, an anonymization-network IP geolocated to Australia, and multiple further attempts between 02:00–08:00 UTC on patch day from varied anonymized infrastructure, "suggesting multiple actors." Amazon states PHP2Shell "is now being broadly exploited" and draws two lessons: coordinated-disclosure dates no longer mark first exploitation, and AI-assisted analysis is collapsing patch-to-exploit time to hours. Five more IOC IPs from October 21 were published with guidance to investigate rather than reflexively block, since the infrastructure is shared.
**Why it matters:** Pre-embargo exploitation means compromise may predate the advisory for every internet-facing PHP server — and with only PHP 8.2+ patched, the unpatchable EOL tail (roughly half of PHP sites per Detectify) is now sitting next to weaponized, actively-researched RCEs.
**Action:** Upgrade to the fixed releases (8.5.12/8.4.27/8.3.36/8.2.35) — the only complete remediation; investigate web logs from October 17 onward for POST requests containing the PHP_SESSION_UPLOAD_PROGRESS string; check for unexpected process execution or file modifications; consider blocking multi-part uploads only after assessing application impact.

**Node.js urgent release: Brotli decoder out-of-bounds write "permits remote code execution," plus 9 flaws and eMudhra CA block** — *Event date: Wednesday, October 21, 2026 (release completed late Wednesday; full advisory details circulated overnight)*
The Node.js project's Wednesday security release fixes 10 flaws across 22.x, 24.x and 26.x — headlined by CVE-2026-111497, an out-of-bounds write in the bundled Brotli decompressor (Node's own copy of Google's Brotli, not user code) that triggers whenever Node decompresses attacker-controlled data via node:zlib or fetch(); the project's rating is High. Fixed versions: 22.23.4, 24.22.1, 26.12.1 — EOL lines such as 20.x get nothing. Other High fixes include two TLS hostname-check bypasses (CVE-2026-106069, CVE-2026-105483) and a dns.resolve null-byte truncation (CVE-2026-105482); the same builds hard-block the eight compromised eMudhra intermediate CA keys (previously trusted since Node skips revocation checks by default). A public PoC dated October 22 reached code execution only against a weakened test build — on standard builds, a crash and limited memory read — and no in-the-wild exploitation has been reported.
**Why it matters:** fetch()-triggered decoder bugs put a RCE-class primitive in front of virtually every Node service that touches the network, and with no in-runtime workaround, the only fix is upgrade-and-rebuild every image. The upstream Brotli fixes (1.2.1/1.1.1/1.0.10) also shipped October 21 — anything else bundling Brotli needs the same update.
**Action:** Upgrade to 22.23.4 / 24.22.1 / 26.12.1 and rebuild all shipped Node images; migrate off EOL lines; Vercel's inbound firewall rules are a stopgap that does not cover fetched Brotli responses.
Source: Node.js project, "Wednesday, October 21, 2026 Security Releases," Oct 21, 2026 — https://nodejs.org/en/blog/vulnerability/october-2026-security-releases
