## Vulnerabilities and patches

**CISA confirms PHP2Shell: KEV addition orders federal patching by Thursday** — *event date: Monday, Oct 26 (KEV listing); BleepingComputer Oct 27 04:20 ET*
CISA added CVE-2026-109618 (out-of-memory corruption) and CVE-2026-109619 (stale internal request-state), the two unauthenticated RCE flaws collectively dubbed PHP2Shell, to its Known Exploited Vulnerabilities catalog on Monday, ordering Federal Civilian Executive Branch agencies to remediate by Thursday under Binding Operational Directive 26-04. TheHackerNews reports both flaws are rated CVSS 9.2 (NVD's listing is carried at 9.8 by aggregators). The listing follows Perplexity detection lead Adel Karimi's Oct 24 honeypot confirmation of working RCE against Apache mod_php on PHP 8.4.26 — the same thread this brief has tracked since Oct 21; pre-patch attack attempts from Cloudflare, Amazon MadPot and others were all previously assessed unsuccessful.
**Why it matters:** KEV + BOD 26-04's Thursday deadline converts the industry-wide scramble into a federal mandate, and it is the US government's first formal confirmation that PHP2Shell is exploited in the wild — expect aggressive exploitation of the ~3.8M PHP hosts with exposed ports (VirusTotal estimate cited by BC) while EOL branches stay unfixed.
**Action:** Patch PHP to 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35 (Windows: the -1 rebuilds) — federal deadline is Thursday; CISA urges all organizations to prioritize KEV flaws.

**Apple backports exploited CoreGraphics zero-day (CVE-2026-86950) to iPhone XS/XR-era devices** — *event date: Monday/Tuesday, Oct 26–27 (backported updates released)*
Apple shipped security updates this week that backport the CoreGraphics out-of-bounds-write fix to devices the September patch left behind: iPhone XS, XS Max, XR, iPad 7th gen, iPad Air 4th gen and later, iPad 9th gen and later, and iPad mini 6th gen and later. The flaw — discovered by Meta Product Security and listed in CISA's KEV on Sept 29 — was exploited in "extremely sophisticated" targeted attacks against individuals on pre-iOS 27 versions, but had only been fixed on iOS 26.7.1 / iPadOS 26.7.1 / macOS Tahoe 26.7.1 / Sequoia 15.8.1; processing a maliciously crafted file can yield arbitrary code execution. Severity: not specified by source (Apple publishes no CVSS); this is one of only two exploited zero-days Apple has fixed this year, alongside February's dyld flaw CVE-2026-20700.
**Why it matters:** For three-plus weeks, the oldest-but-still-supported devices — common in enterprise fleets and kiosk/field use — had a KEV-listed exploited zero-day with no patch at all; that exposure window is now closed, but only if owners actually install the updates.
**Action:** Install the backported updates on all iPhone XS/XR-era and qualifying iPad devices; treat as urgent for executives and high-value targets given the targeted-attack pattern.

Source: DailySecurityReview, "Apple Backports Exploited CoreGraphics Zero-Day Fix to iOS 18," Oct 27, 2026 — https://dailysecurityreview.com/resources/apple-backports-exploited-coregraphics-zero-day-fix-to-ios-18/

**Microsoft Authenticator Android broker flaw (CVE-2026-80097, CVSS 8.6) let any installed app hijack work accounts** — *event date: disclosed by Enclave during the weekend/Monday; press coverage Oct 26–27*
Researchers at Enclave showed that Authenticator for Android's exported `AccountChooserActivity` trusted app-identity fields supplied by the caller instead of verifying the real requesting application: a malicious app with zero declared permissions could impersonate an installed Microsoft client such as Teams and silently receive delegated access, refresh, and ID tokens — enabling reading/sending mail, modifying files/calendars/SharePoint, messaging in Teams as the victim, and (by impersonating Authenticator itself) adding attacker passkeys for durable persistence. Microsoft classified it as improper authentication / local privilege escalation, rated CVSS 8.6, and fixed it in Authenticator 6.2606.4246 — but the fix built in July only reached public disclosure this week.
**Why it matters:** This breaks the implicit assumption that the broker is the trusted root of Android M365 identity — any sideloaded app could mint Graph tokens with no prompt — and passive-detection teams get no telemetry because nothing ever "fails."
**Action:** Confirm every managed Android device runs Authenticator ≥ 6.2606.4246 (enforce via MDM); monitor for unexpected Entra passkey registrations and anomalous Microsoft Graph consent from mobile agents.

## Attacks and campaigns

**"Test-only" Miasma npm worm had already armed 42 real GitHub repos with search-invisible 13 MB payloads** — *event date: Monday, Oct 26 (JFrog report; Register 22:29 UTC)*
SafeDep first tracked the "testmetest" npm campaign Oct 19–25 (18 operator-linked packages) and concluded it was a harmless drill with no victims; JFrog's Monday analysis proved otherwise, finding 42 armed repositories belonging to 11 established owners — hijacked accounts dating back to July. The worm shares code with June's Miasma "Phantom Gyp" worm and adds Mini Shai-Hulud's token-revocation wiper (wipes the home directory if the stolen GitHub token is revoked); it planted execution hooks for AI coding assistants (Claude, Gemini, Cursor, VS Code) and polymorphic wrappers of 12.9–13.7 MB that decode a hidden CI-publisher payload — deliberately sized so GitHub code search never indexes them and the contents API won't return them. A compiled native add-on decrypts and launches the payload only outside CI/sandbox/debugger environments; a second build pulls a loader from the operator's "CementBeetleSteeple" GitHub account (17 campaign repos), which JFrog links to the Socket-documented shellpanel scanner that abused GitHub Actions to exploit cPanel/WHM auth-bypass CVE-2026-41940 (CISA KEV, April).
**Why it matters:** The "too big to search" trick defeats the standard hunt path (code search + contents API) that most org-responses rely on, and the AI-assistant hook files mean developer workstations with agentic tools in the repo path are now a primary detonation surface.
**Action:** Audit repos for unexplained 12–14 MB blobs, `ci-sync`-style branches, and AI-hook config files (Claude/Gemini/Cursor/VS Code execution hooks); rotate any GitHub tokens from affected owners; verify cPanel/WHM is patched.
Source: The Register, "Worm armed 42 GitHub repos by hiding a payload too big to fail," Oct 26, 2026 22:29 UTC — https://www.theregister.com/security/2026/10/26/worm-armed-42-github-repos-by-hiding-a-payload-too-big-to-fail/5305570
Source: JFrog Security Research, "Beyond testmetest: Native Addon Camouflage and 42 Armed GitHub Repositories Reveal a Hidden npm Publisher," Oct 26, 2026 — https://research.jfrog.com/post/beyond-testmetest-42-hijacked-github-repos/

**Australian Signals Directorate severs Amadey botnet controller from 180,000 infected computers** — *event date: Tuesday, Oct 27 (ABC exclusive interview published 5:00am; ASD annual report released same day)*
ASD revealed it penetrated the backend of a criminal Amadey operation and "disconnected that Amadey controller from all those victims" — roughly 180,000 compromised machines globally, including some in Australia, acting deputy DG of intelligence Tauri Gregory told ABC News. Amadey, sold-as-a-service since 2018 (often bundled into pirated software such as fake Photoshop installers, panels resold around US$500), steals credentials and personal data for dark-web resale. In the same interview, DG Abigail Bradshaw published ASD's annual cyber threat report — a 20% year-on-year jump in incidents requiring response — and disclosed that ASD has standing "early warning" protocols with frontier AI labs including OpenAI following what Australia described as the first autonomous AI-agent breach of a government website.
**Why it matters:** Offensive disruptions kill the *controller*, not the implant — the 180k machines remain infected and re-connectable, so detection/remediation duty still sits with defenders; it's also the clearest public statement yet that frontier-model-enabled attacks are driving national cyber doctrine.
Action: If your org or home devices ever ran pirated freeware bundles, re-image rather than just uninstalling, and rotate credentials used on those hosts.
Source: ABC News (Australia), "Disruptions 'inevitable' as AI-powered cyber threats grow, ASD says," Tue 27 Oct 2026 5:00am — https://www.abc.net.au/news/2026-10-27/australian-signals-directorate-ai-cybersecurity-hacking-threats/107309858

**University of Copenhagen breach: 525,000 people's CPR numbers; update adds 20,000 exposed PIN codes** — *event date: confirmed Monday evening, Oct 26 (university update on PINs issued same day)*
The University of Copenhagen confirmed attackers accessed a test environment holding full names, Danish national identity (CPR) numbers, phone numbers and email addresses for ~525,000 people; a Monday update added that PIN codes for a further 20,000 staff and students were exposed, prompting the university to restrict physical access to critical campus locations while it redistributes access codes. The university says the attacker's access is blocked, operational systems show no indication of compromise, and it has reported to the Danish Data Protection Agency under GDPR. (Underlying intrusion detected Tuesday last week; the Monday-evening confirmation and PIN-code update are the in-window developments.)
**Why it matters:** CPR numbers are Denmark's universal identity key — lifetime phishing, social-engineering and fraud exposure for ~9% of the population's records — and the PIN spillover shows test environments keep becoming the soft underbelly of otherwise segmented estates.
**Action:** Affected staff/students should treat unsolicited "official" contacts as hostile until independently verified; defenders should audit non-production environments for production-data copies.

**ENGIE confirms customer data stolen via partner-operated marketing platform** — *event date: Monday, Oct 26 (disclosure to BleepingComputer; article Oct 27 05:25 ET)*
French energy giant ENGIE (90,000+ employees, €71.9B revenue, 30 countries) confirmed attackers stole customer data from a marketing/prospecting platform used by its business partners, with internal IT systems untouched. The breach is limited to French customers; per notification letters, stolen fields include first/last name, mailing address, email, phone, the Delivery Point (PDL) / Metering Point (PCE) identifiers, customer ID and contract number — no banking data. ENGIE cut the attackers' access, notified authorities and each affected customer; no threat group or ransomware gang has claimed it.
**Why it matters:** PDL/PCE identifiers and contract numbers are precisely what realistic utility-bill phishing and account-takeover scams need, echoing last month's Ahold Delhaize partner-platform compromise — third-party marketing tooling keeps emerging as the softest breach surface in large consumer-facing utilities.
**Action:** ENGIE customers in France: expect convincing bill-phishing; verify energy communications through official channels. Security teams: inventory partner-run marketing platforms holding your customer fields.

**Update on previously reported — GMO Onamae.com Desktop Cloud: $50M ransom demand refused, unauthorized FX trades, CEO asks Tokyo for 'proactive cyber defense'** — *event date: Monday/Tuesday, Oct 26–27 (GMO updates + CEO statement)*
Following the Oct 20 confirmation that malware sat on up to 26,739 of its Onamae.com Desktop Cloud VDI servers (ledger: "missed — onamae-desktop-cloud-gmo," Oct 20), GMO Internet disclosed a cascade of new facts: customers report unrecognized operations on their FX trading accounts; attackers probably saw users' trading passwords; GMO has asked brokerages to force-terminate sessions, monitor for unauthorized trades and block trade requests originating from the Desktop Cloud. GMO says it received — and refused — a $50 million payment demand accompanied by threats to publish customer information, is offering a ¥5,000 ($32) condolence payment plus reimbursement of proven trading losses, and warns that some trading apps keep sessions alive even after password changes. CEO Hiroaki Kumagai publicly proposed the service be shut down/"banned" and says he submitted a government proposal for "proactive cyber defense," also claiming GMO's security arm traced attacks on ~20 Japanese companies to misuse of ARTEX — the same autonomous AI pentest framework Microsoft tied to the ConnectWise/Storm-0940 and Korean ARTEX-arrest threads.
**Why it matters:** A hosting provider whose core selling point was a *secure trading environment* becoming a credential-theft vector — and its CEO lobbying for preemptive national cyber defense as the remedy — is a landmark in the "AI-era attack industrialization" narrative now dominating APAC security policy.
**Action:** If you used Onamae Desktop Cloud for securities/FX: change trading passwords from a non-cloud device AND have the broker kill all live sessions (password change alone may not evict attackers).

## Defensive tools and advisories

**Blue Initiative launches: free maritime vulnerability index with ~30,000 curated entries** — *event date: Tuesday, Oct 27 (public launch; SecurityWeek 03:14 ET)*
Cydome, Japan's ClassNK classification society, Bureau Veritas, the MTS-ISAC and Rakuten Maritime launched Blue Initiative, a freely accessible database indexing IT and OT vulnerabilities relevant to ships and ports: nearly 30,000 entries, 2,000+ CVSS-critical, 580+ confirmed exploited in the wild, and 37 in products built specifically for maritime use. Entries are largely auto-mapped from CISA ICS advisories and the KEV catalog with hand-written analyst notes on what each flaw means aboard a vessel, plus subscription alerts for new critical/high entries; community contributions are open.
**Why it matters:** Maritime OT has lacked any curated, exploitation-aware vulnerability view — operators previously drowned in generic NVD/ICS noise — and a launch backed by the two biggest classification societies plus an ISAC gives it real industry standing; the 580+ known-exploited figure should re-prioritize onboard patching programs overnight.
**Action:** Maritime/port security teams: subscribe to alerts and reconcile fleet inventories against the index (https://blue-initiative.org/cves).
Source: SecurityWeek, "Maritime Coalition Launches Free Vulnerability Database for Ship and Port Systems," Oct 27, 2026 3:14 AM ET — https://www.securityweek.com/maritime-coalition-launches-free-vulnerability-database-for-ship-and-port-systems/
Source: Blue Initiative (official site, live index count 29,523) — https://blue-initiative.org/
